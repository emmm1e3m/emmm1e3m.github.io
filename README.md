# 旅行饼狗

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。GitHub Pages 根首页只提供入口，游戏固定位于：

```text
/AllForSUXINHAO/TravellingBingo/
```

## 一键本地启动

需要 Node.js 24 和 npm 11 或更高版本。Windows 下双击根目录的 [启动旅行饼狗.cmd](./启动旅行饼狗.cmd)：

- 自动切换到仓库根目录并检查 Node.js、npm 与依赖；
- 使用固定的 `localhost:5173` 启动开发服务器；
- 自动打开 `http://localhost:5173/AllForSUXINHAO/TravellingBingo/`；
- 端口被占用或启动失败时保留窗口和中文错误信息。

也可以手动启动：

```powershell
npm ci
npm run dev -- --host localhost --port 5173 --strictPort --open "/AllForSUXINHAO/TravellingBingo/"
```

## V4 游玩规则

- 新活动的默认读条为 1 分 12 秒。旅行、刷播、冲热、弹琴和睡觉都先二次确认；进行中或已完成待领取的活动都可以取消。取消不增加陪伴天数，也不返还开始时已经消耗的补给。
- 活动保存绝对的 `startedAt`、`endsAt` 与奖励快照。退出、读档或以后再次调整默认时长，都不会重算已经开始的任务。
- 五类饼屋活动每成功领取一次，或一轮苹果钟首次到点完成，陪伴天数增加一天。睡觉另得 1🍎并刷新意愿；取消、普通现实停留结算和待办操作都不增加天数。
- 冰箱有五种原有补给，以及 ⚡瓶装速度魔法和 ✨瓶装活力魔法。速度魔法可让当前读条立刻完成；活力魔法让接下来七个相伴日的活动意愿全部为真。苹果钟完成增加的陪伴日同样消耗一天活力，到第七天时结束效果并恢复当日偏好。
- 左下 `↩️` 用于请求取消当前读条，右上 `ℹ️` 打开简洁的“铲铲饼屋的小纸条”，右下按钮在旅行饼狗与现实生活之间切换。点击房间空白会回到当前任务与意愿概览；信息栏可从右上收起。
- 房间使用用户提供的 1098 × 1433 透明原图作为唯一母版，网页只做等比缩放与无损 WebP 编码。床、两台电脑、衣架、电子琴、冰箱、唱片机、收藏墙和房门都有按母版像素锁定的饼狗中心点。

## 收藏、好友与音乐

- 明信片和百万直拍从未拥有项中随机且不重复获得；全站第一按时间顺序从 Dynamite 到 POWER 由旧到新不重复获得。存档不保存目录总数、分类解锁列表或“下一项”指针，因此以后追加收藏时旧档仍能识别新内容。
- 旅行先判断是否遇见朋友；遇见朋友时不会同时获得明信片。弹琴只可能召回已经认识的朋友，不会凭音乐解锁新朋友。
- 当前目录包含 100 张明信片、30 张百万直拍、8 项全站第一和 5 位好友。收藏墙只显示已经获得或遇见的内容；详情图片先铺满裁切，点击后可完整全屏查看与下载。
- 电子琴覆盖 C4–B6 三个完整八度，共 36 个半音；界面分三排，中间一排从 C5 开始，电脑键盘只映射白键。
- 唱片机和视频收藏共用一个持久 B 站 iframe。选曲或打开视频详情会发送自动播放请求；收起信息栏或切换维度不会自动卸载它，玩家也可明确停止。
- 唱片机可以在“百万直拍精选”和已保存的自定义曲库间切换；输入名称及每行一个 BV 号或完整 Bilibili 视频链接即可创建或更新列表，重复曲目会去重。播放器会保存当前曲目、起播秒数与列表/单曲/随机模式。B 站 iframe 跨域，网页不能可靠读取真实暂停、真实进度或播放结束，所以模式只影响玩家主动切歌，不能承诺自动续播；浏览器也可能拦截有声自动播放。

## 现实生活维度

- 二楼电脑的“数据”页保留真实刷播与冲热入口说明，并提供运行组链接；当前操作步骤仍是占位说明。
- 一楼电脑的“工作”页提供 5、25、50 分钟苹果钟、已解锁明信片背景和持久化待办清单。待办可创建、编辑、变更完成状态和删除。
- 苹果钟到达绝对结束时间后的首次完成处理会增加一天陪伴天数，并签发一次提醒请求；重复检查、未到点或提前取消都不会重复加天。浏览器通知必须由用户主动授权；页面完全关闭、浏览器休眠或系统冻结时不保证准时弹出，重新聚焦页面后会按绝对时间补处理。
- 在现实维度每停留完整 10 分钟积累 1🍎。返回游戏时选择“是的🥰”获得全额，选择“没有🥺”获得向下取整的一半；这项停留结算本身不增加陪伴天数。

## 存档与浏览器能力边界

- 新导出使用 `schemaVersion: 4` 与 `gameVersion: 0.4.0-demo.1`。导入严格支持 V1、V2、V3、V4：先校验原始 payload 摘要，再迁移、规范、协调当前目录并做最终语义校验。
- 存档包含正在进行的活动、现实停留与待结算奖励、魔法状态、待办、苹果钟和播放器设置；不复制收藏目录或视频元数据。
- 标题页和房间都有显式“检查新布置”，实际调用 Service Worker 的更新检查。它不会绕过未保存进度保护强制刷新。
- 10 Hz、增益 0.01 的守候音频只在明确用户手势后创建，可从状态栏暂停或恢复。它只是浏览器保活的尽力措施，浏览器、系统节能或后台策略仍可能挂起页面。

完整产品、领域、存档、视觉与验收规则见 [docs/旅行饼狗网页完整实现方案.md](./docs/旅行饼狗网页完整实现方案.md)。

## 目录约定

```text
AllForSUXINHAO/TravellingBingo/   # 游戏源码与公开运行时资源
docs/                             # 纲要、实现方案与交付说明
research/travelling-bingo/        # 结构化资料、来源与锁定清单
resources/raw/travelling-bingo/   # 本地母版、原图和字体源
scripts/                          # 素材、站点组装与校验脚本
```

房屋唯一母版为 `resources/raw/travelling-bingo/generated/chan-chan-house-master.png`；公开派生图保留现有兼容文件名 `chan-chan-house-v2-768.webp` 与 `chan-chan-house-v2-1098.webp`。网页与 PWA 图标使用饼狗头像 PNG。真实明信片和海报不使用生成图代替。

## 常用命令

```powershell
npm run verify
npm run build
npm run site:assemble
npm run site:verify
npm run test:e2e
```

`npm run verify` 包含格式、Lint、类型、单元测试、视频目录与素材校验；浏览器 E2E 需要单独运行 `npm run test:e2e`。

清理可重建产物前先预览：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/maintenance/clean-workspace.ps1 -WhatIf
```

确认后去掉 `-WhatIf`。脚本只处理仓库根目录中明确列入白名单的构建与测试目录，不处理 `node_modules/`、`resources/`、`research/` 或字体。
