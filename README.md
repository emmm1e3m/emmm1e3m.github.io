# 旅行饼狗

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。GitHub Pages 根首页只提供入口，游戏固定位于：

```text
/AllForSUXINHAO/TravellingBingo/
```

## 一键本地启动

需要 Node.js 24 和 npm 11 或更高版本。Windows 下双击根目录的 [启动旅行饼狗.cmd](./启动旅行饼狗.cmd)：

- 自动切换到仓库根目录并检查 Node.js、npm 与依赖；
- 使用固定的 `localhost:5173` 启动开发服务器；
- 自动打开 `http://localhost:5173/AllForSUXINHAO/TravellingBingo/`；
- 端口被占用或启动失败时保留窗口和中文错误信息。

也可以手动启动：

```powershell
npm ci
npm run dev -- --host localhost --port 5173 --strictPort --open "/AllForSUXINHAO/TravellingBingo/"
```

## V10 游玩规则

- 新活动的默认读条为 10 秒。旅行、刷播、冲热、弹琴和睡觉都先二次确认；进行中或已完成待领取的活动都可以取消。取消不增加陪伴天数，也不返还开始时已经消耗的补给。
- 活动保存绝对的 `startedAt`、`endsAt` 与奖励快照。退出、读档或以后再次调整默认时长，都不会重算已经开始的任务。
- 五类饼屋活动每成功领取一次，或一轮完整苹果钟结束，陪伴天数增加一天。睡觉另得 1🍎并刷新意愿；取消、普通现实停留结算和待办操作都不增加天数。
- 今日 Bingo 的三项任务全部完成后以 `√` 保留，等下一次游戏日（陪伴日）推进时再刷新；任一任务尚未完成，则跨游戏日继承原任务与完成状态。成功领取任一种饼屋活动，或完成一轮完整苹果钟，都会推进一个游戏日。
- 新签发的单条 Bingo 任务最多奖励 3🍎；已经写入旧存档的任务仍按自身奖励快照兑现。
- 新任务只从当前可完成的模板中签发；例如拥有至少一项全站第一后才会出现“重看全站第一”，需要查看两份不同收藏的任务则要求已有至少两份有效收藏。读取缓存/本地存档或在 DEBUG 中移除收藏后，合法但已经无法完成的未完成任务会确定性换成可完成任务；已完成任务和仍可完成任务的进度保留，畸形任务板仍会被拒绝。
- 与饼狗完成一次有效互动后的提示统一为“互动完成”。
- 冰箱有五种原有补给，以及 ⚡瓶装速度魔法和 ✨瓶装活力魔法。速度魔法单价为 2🍎，可让当前读条立刻完成；🍎苹果旅行便当让当次旅行遇友概率翻倍，🍀幸运苹果让当次对应收藏概率翻倍，同类加成只取最高值而不复合叠加；活力魔法单价为 7🍎，让接下来七个相伴日的活动意愿全部为真。
- `ℹ️`、`↩️`、`🔃` 统一位于房间区域的角落。切换维度前会先显示介绍并确认；点击房间空白会回到当前任务与意愿概览。
- 状态栏按页面导航与游戏状态分列对齐；现实计时、活力、🍎、收藏墙和 DEBUG 状态都可点击跳到对应页面或操作。原先笼统的“状态正常”由低活力、中等活力、高活力或活力满满取代；刷播进度留在刷播信息页与独立窗口中。
- 房间使用用户提供的 1098 × 1433 透明原图作为唯一母版，网页只做等比缩放与无损 WebP 编码，并以 `contain` 完整显示，不拉伸、不裁切；宽屏横向房间区域允许保留透明侧边留白。床、两台电脑、衣架、电子琴、冰箱、唱片机、收藏墙和房门都有按母版像素锁定的饼狗中心点。

## 收藏、好友与音乐

- 明信片和百万直拍从未拥有项中随机且不重复获得；百万直拍基础概率为 30%，使用幸运苹果后为 60%。全站第一基础概率为 15%，并按时间顺序从 Dynamite 到 POWER 由旧到新不重复获得。幸运苹果始终让对应收藏的未增强基础概率翻倍并封顶为 100%，不会与其他同类加成复合叠加。
- 旅行以 10% 基础概率先判断是否遇见朋友；🍎苹果旅行便当让这份未增强基础概率翻倍，默认即从 10% 变为 20%。遇见朋友时不会同时获得明信片，并固定带回对应道具。课代饼、三好兔、心好兔、信号狗、饼哩饼哩在旅行中依次赠送 2/3/4/3/2🍎，已经认识的朋友仍可再次遇见并照常赠礼。弹琴只可能召回已经认识的朋友，不会凭音乐解锁新朋友；每位已认识朋友增加 15% 来访概率，五位朋友依次赠送 4/6/8/6/4🍎，所以认识的朋友越多，每次弹琴的期望赠礼越高。
- 当前目录包含 100 张明信片、30 张百万直拍、8 项全站第一和 5 位好友。收藏墙只显示已经获得或遇见的内容；卡片缩略图可铺满裁切，收藏详情、全屏预览和明信片选择器使用 `contain` 保留完整画面并允许留白，苹果钟运行背景使用 `cover` 铺满并允许裁切；收藏图可下载。
- 收藏墙标题和已出现的分类会显示当前拥有进度；未集齐时隐藏总数，例如“好朋友们【4/?】”，集齐后才显示“【5/5】”。进度由当前目录动态派生，不写死在存档里。
- 电子琴覆盖 C3–B6 四个完整八度，共 48 个半音；界面从上到下按 C6、C5、C4、C3 排列，白键依次映射 `1–7`、`Q–U`、`A–J`、`Z–M`。
- 唱片机固定提供八首全站第一，从 Dynamite 到 POWER 按时间顺序排列，不提供自定义曲库。列表、单曲和随机模式均可使用上一首、下一首；单曲模式的主动切歌仍会移动到相邻曲目。
- 唱片机与视频详情共用一个持久播放器。选曲或打开视频详情会从头请求自动播放；画面展开时可直接操作 B 站播放器，收起时画面不可操作，也可用游戏控件显示/隐藏画面、暂停/继续或取消播放。父页无法感知用户在 B 站画面里手动暂停或拖动，游戏估算计时不会随之同步；切换信息内容、收藏墙或维度不会意外中断播放器。

## 现实生活维度

- 现实维度在电脑端和移动端都可进入，可以使用刷播、待办与苹果钟。
- 二楼电脑拆分为“刷播”和“冲热（开发中）”；冲热目前仅在电脑端开放，冲热页提供“前往字母建设站”入口。一楼电脑的“工作”先显示待办，再显示专门的明信片选择器。
- 刷播只保留单一模式。主游戏设置收藏夹、自测视频和定时停止，然后同步打开一个 430 × 760 的独立刷播页；独立页也可以自行修改这三项设置并手动开始。自测视频接受单个 BV 号或完整 B 站视频链接，也可以留空；有效输入会规范为 BV 号并随存档保留。移动端使用前请先用自测视频测试，并允许本站弹出窗口。
- 刷播收藏夹的唯一运行源是同源 `favourites/3682220021.txt`（刷播）和 `favourites/3986840044.txt`（测试），每行一个 BV。它们随构建复制到站点；只有显式执行 `npm run research:sync:favourites` 才联网刷新，浏览器运行时不请求 B 站收藏夹 API，也不使用 HTML/CORS 代理。
- 独立页每轮重新随机排列所选收藏夹，自测视频去重后固定放在末尾，并每隔 5 秒创建一个带 `autoplay=1&muted=1&t=0` 的官方播放器 iframe。最后一个 iframe 创建后，按墙上时钟等待默认 310 秒；到期销毁本轮全部 iframe并立即开始下一轮。关闭独立页 DEBUG 时播放器只隐藏、不跳过创建；页面运行期间会播放低音量保活音频。
- 独立页点击大标题 5 次并输入密码 `SUperView` 可打开自己的 DEBUG，修改本页轮次间隔并选择是否显示播放器；它与主游戏 DEBUG 完全解耦。可按小时设置定时停止，0 或留空表示不限时，最长 24 小时。刷播会使用当前浏览器账号，登录时每天不要超过 5 小时。
- 独立页与主游戏用同源 `postMessage` 回传轮次和结束状态，并在同源 `localStorage` 保留最近 10 次任务；一次启动即使包含多轮也只记一条起止、轮数和完成/停止记录。页面冻结后恢复时，调度器按 `Date.now()` 的绝对截止时间校准，不按“一秒加一秒”的计数器补跑漏掉的多轮；关闭独立页则停止本页调度。
- 官方 iframe 的 B 站文档会按浏览器策略携带当前浏览器可用于 B 站的 Cookie，并由 B 站脚本自行发起媒体、统计或心跳请求。本站父页受同源策略限制，不能读取 Cookie、iframe DOM、真实播放状态或网络响应，也不能确认计数是否成功；父页只负责创建、计时和销毁 iframe。
- 苹果钟提供 25+5、50+10、90+15 三组专注与休息周期。启动后把选定明信片作为 `cover` 全屏背景，配合陪伴饼狗、待办和可操作的游戏播放器控件；完成整轮才增加一天陪伴天数。
- 苹果钟与待办使用绝对截止时间并签发一次提醒请求；页面关闭、浏览器休眠或系统冻结时不保证准时弹出，重新聚焦页面后会补处理。
- 在现实维度每实际计时完整 10 分钟积累 1🍎。状态栏只显示分钟，点击它等同于返回游戏维度。页面每 60 秒把有效时长写入缓存；点“离开”、离开旅程或触发 `pagehide` 时立即暂停，异常退出最多保留到最后一次心跳。继续缓存只从已累计时长接着计时，不补离线时段。不足 1🍎时直接返回；达到 1🍎后，选择“是的🥰”获得全额，选择“没有🥺”获得向下取整的一半。这项结算本身不增加陪伴天数。

## 存档与浏览器能力边界

- 浏览器缓存是日常主存档。标题页在存在缓存时显示“继续”，并始终提供“全新旅程”和“本地存档”；`.bingo` 文件继续用于备份与跨浏览器导入。
- 通过“全新旅程”或“本地存档”覆盖缓存前、检测到网页更新时会先下载旧档；首次获得新的全站第一或认识新朋友时会下载关键节点存档，并每隔三天请求一次周期备份。
- 新导出使用 `schemaVersion: 10` 与 `gameVersion: 0.10.0-demo.1`。导入严格支持 V1–V10：先校验原始 payload 摘要，再逐代迁移、规范、协调当前目录并做最终语义校验。
- 旧缓存迁移或目录协调后，会把 V10 payload、`gameVersion` 与缓存更新时间一起写回；浏览器缓存外层 `cacheVersion` 仍保持 1。历史 V6→V7 的刷播记录迁移、V7→V8 的旧设置和 V8→V9 的现实计时租约规则都保持冻结；V9→V10 保留自测 BV，以默认刷播收藏夹替换已经退役的维度穿透字段。
- 存档包含正在进行的活动、现实停留与待结算奖励、魔法状态、待办、苹果钟、播放器的当前曲目和循环模式、刷播累计轮次与最近 10 次任务记录，以及单个可选自测 BV 和所选收藏夹；独立页的运行中 iframe、定时器、保活音频和 DEBUG 设置不写入 `.bingo`。
- 标题页在两个圆形头像下方、缓存记录上方展示更新公告；房间左上角的 `#️⃣` 可打开同一公告。当前公告会明确提示“目前刷播功能不稳定，请暂时不要通过此方式刷播”。首次进入或从旅程返回标题页时各自动检查一次更新，同一次停留不会因页面重绘重复检查，按钮仍可手动再查；检测到新版本时会先备份缓存进度，再提供更新安装。
- 守候音频只在进入旅程的明确用户手势后创建并保持开启，不在状态栏暴露技术开关。浏览器、系统节能或后台策略仍可能挂起页面。
- 以触屏为主的移动设备在旅程运行且页面可见时会请求屏幕常亮；页面隐藏时释放，重新可见时再请求。浏览器不支持或拒绝权限不会阻断游戏，也不代表切到后台后仍能持续运行。

完整产品、领域、存档、视觉与验收规则见 [docs/旅行饼狗网页完整实现方案.md](./docs/旅行饼狗网页完整实现方案.md)。

## 目录约定

```text
AllForSUXINHAO/TravellingBingo/   # 游戏源码与公开运行时资源
  └─ favourites/                  # 两份刷播收藏夹 BV 文本快照
docs/                             # 纲要、实现方案与交付说明
research/travelling-bingo/        # 结构化资料、来源与锁定清单
resources/raw/travelling-bingo/   # 本地母版、原图和字体源
scripts/                          # 素材、站点组装与校验脚本
```

房屋唯一母版为 `resources/raw/travelling-bingo/generated/chan-chan-house-master.png`；公开派生图保留现有兼容文件名 `chan-chan-house-v2-768.webp` 与 `chan-chan-house-v2-1098.webp`。网页与 PWA 图标使用饼狗头像 PNG。真实明信片和海报不使用生成图代替。

两款公开 WOFF2 保持原有文件名，覆盖《现代汉语常用字表》的 2500 个常用字、ASCII、中文标点和当前运行时额外用字。固定字表保存在 `scripts/assets/data/modern-chinese-common-2500.txt`；新增普通常用字文案无需重新生成字体，新增表外字时 `npm run assets:verify` 会明确提示重建。

## 常用命令

```powershell
npm run verify
npm run build
npm run site:assemble
npm run site:verify
npm run test:e2e
```

`npm run verify` 包含格式、Lint、类型、单元测试、视频目录、两份刷播收藏夹文本与素材校验；浏览器 E2E 需要单独运行 `npm run test:e2e`。

清理可重建产物前先预览：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/maintenance/clean-workspace.ps1 -WhatIf
```

确认后去掉 `-WhatIf`。脚本只处理仓库根目录中明确列入白名单的构建与测试目录，不处理 `node_modules/`、`resources/`、`research/` 或字体。
