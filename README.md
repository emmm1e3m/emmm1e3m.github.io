# 旅行饼狗

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。GitHub Pages 根首页只提供入口，游戏固定位于：

```text
/AllForSUXINHAO/TravellingBingo/
```

## 一键本地启动

需要 Node.js 24 和 npm 11 或更高版本。Windows 下双击根目录的 [启动旅行饼狗.cmd](./启动旅行饼狗.cmd)：

- 自动切换到仓库根目录并检查 Node.js、npm 与依赖；
- 使用固定的 `localhost:5173` 启动开发服务器；
- 自动打开 `http://localhost:5173/AllForSUXINHAO/TravellingBingo/`；
- 端口被占用或启动失败时保留窗口和中文错误信息。

也可以手动启动：

```powershell
npm ci
npm run dev -- --host localhost --port 5173 --strictPort --open "/AllForSUXINHAO/TravellingBingo/"
```

## V8 游玩规则

- 新活动的默认读条为 10 秒。旅行、刷播、冲热、弹琴和睡觉都先二次确认；进行中或已完成待领取的活动都可以取消。取消不增加陪伴天数，也不返还开始时已经消耗的补给。
- 活动保存绝对的 `startedAt`、`endsAt` 与奖励快照。退出、读档或以后再次调整默认时长，都不会重算已经开始的任务。
- 五类饼屋活动每成功领取一次，或一轮完整苹果钟结束，陪伴天数增加一天。睡觉另得 1🍎并刷新意愿；取消、普通现实停留结算和待办操作都不增加天数。
- 今日 Bingo 的三项任务全部完成后以 `√` 保留，等下一次游戏日（陪伴日）推进时再刷新；任一任务尚未完成，则跨游戏日继承原任务与完成状态。成功领取任一种饼屋活动，或完成一轮完整苹果钟，都会推进一个游戏日。
- 新任务只从当前可完成的模板中签发；例如拥有至少一项全站第一后才会出现“重看全站第一”，需要查看两份不同收藏的任务则要求已有至少两份有效收藏。读取缓存/本地存档或在 DEBUG 中移除收藏后，合法但已经无法完成的未完成任务会确定性换成可完成任务；已完成任务和仍可完成任务的进度保留，畸形任务板仍会被拒绝。
- 冰箱有五种原有补给，以及 ⚡瓶装速度魔法和 ✨瓶装活力魔法。速度魔法单价为 2🍎，可让当前读条立刻完成；幸运苹果把对应收藏概率翻倍；活力魔法单价为 7🍎，让接下来七个相伴日的活动意愿全部为真。
- `ℹ️`、`↩️`、`🔃` 统一位于房间区域的角落。切换维度前会先显示介绍并确认；点击房间空白会回到当前任务与意愿概览。
- 房间使用用户提供的 1098 × 1433 透明原图作为唯一母版，网页只做等比缩放与无损 WebP 编码，并以 `contain` 完整显示，不拉伸、不裁切；宽屏横向房间区域允许保留透明侧边留白。床、两台电脑、衣架、电子琴、冰箱、唱片机、收藏墙和房门都有按母版像素锁定的饼狗中心点。

## 收藏、好友与音乐

- 明信片和百万直拍从未拥有项中随机且不重复获得；百万直拍基础概率为 30%，使用幸运苹果后为 60%。全站第一基础概率为 15%，并按时间顺序从 Dynamite 到 POWER 由旧到新不重复获得。存档不保存目录总数、分类解锁列表或“下一项”指针，因此以后追加收藏时旧档仍能识别新内容。
- 旅行以 10% 基础概率先判断是否遇见朋友；遇见朋友时不会同时获得明信片，并固定带回对应道具。课代饼、三好兔、心好兔、信号狗、饼哩饼哩在旅行中依次赠送 2/3/4/3/2🍎，已经认识的朋友仍可再次遇见并照常赠礼。弹琴只可能召回已经认识的朋友，不会凭音乐解锁新朋友；每位已认识朋友增加 15% 来访概率，五位朋友依次赠送 4/6/8/6/4🍎，所以认识的朋友越多，每次弹琴的期望赠礼越高。
- 当前目录包含 100 张明信片、30 张百万直拍、8 项全站第一和 5 位好友。收藏墙只显示已经获得或遇见的内容；卡片缩略图可铺满裁切，收藏详情、全屏预览和明信片选择器使用 `contain` 保留完整画面并允许留白，苹果钟运行背景使用 `cover` 铺满并允许裁切；收藏图可下载。
- 电子琴覆盖 C3–B6 四个完整八度，共 48 个半音；界面从上到下按 C6、C5、C4、C3 排列，白键依次映射 `1–7`、`Q–U`、`A–J`、`Z–M`。
- 唱片机固定提供八首全站第一，从 Dynamite 到 POWER 按时间顺序排列，不提供自定义曲库。列表、单曲和随机模式均可使用上一首、下一首；单曲模式的主动切歌仍会移动到相邻曲目。
- 唱片机与视频详情共用一个持久播放器。选曲或打开视频详情会从头请求自动播放；画面展开时可直接操作 B 站播放器，收起时画面不可操作，也可用游戏控件显示/隐藏画面、暂停/继续或取消播放。父页无法感知用户在 B 站画面里手动暂停或拖动，游戏估算计时不会随之同步；切换信息内容、收藏墙或维度不会意外中断播放器。

## 现实生活维度

- 现实维度只允许具备鼠标或触控板精细指针能力的 PC 浏览器进入；移动端读到停留在现实维度的旧存档时，只提供安全返回饼屋并结算的入口。
- 二楼电脑拆分为“刷播”和“冲热（开发中）”；冲热页提供“前往字母建设站”入口。一楼电脑的“工作”先显示待办，再显示专门的明信片选择器。
- 刷播只允许额外填写一个可选的自测视频 BV 号，留空时完全使用本站静态列表；这个 BV 号会随存档保留。其余视频来自 `fid=3963921644` 在构建期生成的同源 `data/video-catalog.json` 快照，运行时不访问 B 站收藏夹 API，也不使用跨域代理。
- 登录刷播通过弹出窗口或新标签页依次打开带 `autoplay=1&t=0` 的标准 B 站视频页；实验性的“维度穿透”游客刷播使用不可交互的官方播放器 iframe。两种方式互斥，切换游戏/现实维度不会中断正在运行的方式；开启维度穿透后，只有没有登录刷播时才自动运行游客刷播。
- 两种刷播共享自测 BV、视频间隔和轮次间隔：默认每个视频间隔 8 秒，可调为 1–60 秒；本轮最后一个页面打开或 iframe 创建后等待 310 秒，再开始下一轮。游客刷播会让本轮 iframe 保留完整一轮，轮次结束时统一移除并创建下一轮；顶栏跨维度显示游客刷播的运行时间与当前轮次。
- 可按小时设置本次任务的定时停止，0 或留空表示不限时，最长 24 小时；登录时尽量不要连续刷播超过 5 小时。打开步骤、轮次和任务限时共用一个一次性定时器；页面恢复后只处理当前到期步骤，不补开多轮。最近保留 10 次任务，一次启动包含多轮也只写一条起止、轮数和完成/停止记录，0 轮任务同样记录。DEBUG 可在本次页面会话把轮次时长设为 1–3600 秒，当前轮保持原时长，从下一轮开始生效。
- 跨站页面和 iframe 的加载都只是请求尝试；游戏不读取 B 站页面内部状态，也不承诺视频真实播放、播放完成或计数增加。
- 苹果钟提供 25+5、50+10、90+15 三组专注与休息周期。启动后把选定明信片作为 `cover` 全屏背景，配合陪伴饼狗、待办和可操作的游戏播放器控件；完成整轮才增加一天陪伴天数。
- 苹果钟与待办使用绝对截止时间并签发一次提醒请求；页面关闭、浏览器休眠或系统冻结时不保证准时弹出，重新聚焦页面后会补处理。
- 在现实维度每停留完整 10 分钟积累 1🍎。返回游戏时选择“是的🥰”获得全额，选择“没有🥺”获得向下取整的一半；这项停留结算本身不增加陪伴天数。

## 存档与浏览器能力边界

- 浏览器缓存是日常主存档。标题页在存在缓存时显示“继续”，并始终提供“全新旅程”和“本地存档”；`.bingo` 文件继续用于备份与跨浏览器导入。
- 通过“全新旅程”或“本地存档”覆盖缓存前、检测到网页更新时会先下载旧档；首次获得新的全站第一或认识新朋友时会下载关键节点存档，并每隔三天请求一次周期备份。
- 新导出使用 `schemaVersion: 8` 与 `gameVersion: 0.8.0-demo.1`。导入严格支持 V1–V8：先校验原始 payload 摘要，再迁移、规范、协调当前目录并做最终语义校验。
- 旧缓存迁移或目录协调后，会把 V8 payload、`gameVersion` 与缓存更新时间一起写回；浏览器缓存外层 `cacheVersion` 仍保持 1。历史 V6→V7 迁移仍将每条旧刷播轮次独立转换成一条 legacy 任务记录，不按时间猜测合并；V7→V8 只新增默认关闭的维度穿透设置与空自测 BV。
- 存档包含正在进行的活动、现实停留与待结算奖励、魔法状态、待办、苹果钟、播放器的当前曲目和循环模式、刷播累计轮次与最近 10 次任务记录，以及单个可选自测 BV 和维度穿透开关；重新打开页面不会恢复正在运行的刷播或播放器进度，也不复制收藏目录或视频元数据。
- “检查更新”只保留在标题页，结果使用临时提示；检测到新版本时会先备份缓存进度，再提供更新安装。
- 守候音频只在进入旅程的明确用户手势后创建并保持开启，不在状态栏暴露技术开关。浏览器、系统节能或后台策略仍可能挂起页面。
- 以触屏为主的移动设备在旅程运行且页面可见时会请求屏幕常亮；页面隐藏时释放，重新可见时再请求。浏览器不支持或拒绝权限不会阻断游戏，也不代表切到后台后仍能持续运行。

完整产品、领域、存档、视觉与验收规则见 [docs/旅行饼狗网页完整实现方案.md](./docs/旅行饼狗网页完整实现方案.md)。

## 目录约定

```text
AllForSUXINHAO/TravellingBingo/   # 游戏源码与公开运行时资源
docs/                             # 纲要、实现方案与交付说明
research/travelling-bingo/        # 结构化资料、来源与锁定清单
resources/raw/travelling-bingo/   # 本地母版、原图和字体源
scripts/                          # 素材、站点组装与校验脚本
```

房屋唯一母版为 `resources/raw/travelling-bingo/generated/chan-chan-house-master.png`；公开派生图保留现有兼容文件名 `chan-chan-house-v2-768.webp` 与 `chan-chan-house-v2-1098.webp`。网页与 PWA 图标使用饼狗头像 PNG。真实明信片和海报不使用生成图代替。

两款公开 WOFF2 保持原有文件名，覆盖《现代汉语常用字表》的 2500 个常用字、ASCII、中文标点和当前运行时额外用字。固定字表保存在 `scripts/assets/data/modern-chinese-common-2500.txt`；新增普通常用字文案无需重新生成字体，新增表外字时 `npm run assets:verify` 会明确提示重建。

## 常用命令

```powershell
npm run verify
npm run build
npm run site:assemble
npm run site:verify
npm run test:e2e
```

`npm run verify` 包含格式、Lint、类型、单元测试、视频目录与素材校验；浏览器 E2E 需要单独运行 `npm run test:e2e`。

清理可重建产物前先预览：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/maintenance/clean-workspace.ps1 -WhatIf
```

确认后去掉 `-WhatIf`。脚本只处理仓库根目录中明确列入白名单的构建与测试目录，不处理 `node_modules/`、`resources/`、`research/` 或字体。
