# 旅行饼狗交付说明

## 本轮目标

本轮是对首版 Demo 的完整 v2 精修，重点不是增加更多面板，而是把房间、饼狗、任务、苹果经济和收藏惊喜串成一个自洽的游玩循环。

## 已确定的 v2 规则

- 游戏位置保持为 `/AllForSUXINHAO/TravellingBingo/`，`AllForSUXINHAO/` 只容纳这一个游戏。
- 常规活动间隔是 112 秒，倒计时继续采用绝对时间，页面切到后台后不会丢失进度。进行中活动的 `startedAt / endsAt` 会随 `.bingo` 保存；读档继续按原 `endsAt` 判断，之后增加默认时长也不会延长已经开始的活动。
- 房间同时给出三条 Bingo 任务。每条完成时立即奖励苹果；三条都完成后播放 `Bingo!` 反馈并自动换成新的三条。
- 任务负责获得苹果，向冰箱中补充道具负责花费苹果，旅行、刷播和冲热只产出收藏或朋友事件。同一流程不会又花苹果又返还苹果。
- 饼狗会有暂时不想做的事。被拒绝的操作不扣道具；去床铺睡一觉会经过变暗、夜晚、重新变亮的转场，然后刷新活动偏好。
- 点房间的文字热点会让饼狗走到对应区域。它在某处忙碌时，该处的热点会暂时消失；点饼狗本身展开行动菜单。
- 饼狗出门后不在房间中显示。刷播和冲热时它会出现在电脑区域。
- 全站第一默认掉落概率为 10%，不叠加会改变长期概率的保底。朋友相遇和各类收藏的概率与它一起放在统一配置中，DEBUG 可直接调整；不维护预制的全收集存档，“一键全收集”会按当前收藏目录即时生成调试状态。
- 幸运苹果使当次对应收藏的掉落概率增加 20 个百分点，苹果旅行便当使当次旅行遇见朋友的概率增加 15 个百分点，两者都封顶 100%。基础收藏掉落率已经是 100% 或对应分类已经集齐时，幸运苹果不可使用，也不会扣除。
- 收藏墙名为“饼狗的收藏墙”。未获得的项目不显示灰色占位，未解锁的分类也不预告；已获得的内容按时间由新到旧排列。只有当前目录全部集齐后才显示完成状态。
- 明信片和百万直拍只在当前未拥有集合中随机选取。全站第一不乱序，按 `chronology` 从 Dynamite 开始由旧到新逐个获得，当前目录最新项是 POWER。三类收藏都不会再次选中已拥有项。
- 收藏推进只依赖存档中的已拥有 ID 集合，首获时间用于展示排序；存档不记录目录总数、“下一项”索引或分类解锁列表。以后向目录增加收藏时，旧存档会自动把新 ID 视为未拥有。通用目录 schema 只验证时间序列完整并从 Dynamite 开始，不把 POWER 写死为永久末项。
- 海报缩略图使用铺满裁切，不留白边。右上角收藏入口使用 `🖼️`，房间状态入口使用 `Bingo!`。
- “奇迹饼狗”展示“测试什么样的舞台适合你”，按钮会在新窗口打开 [Bilibili 舞台测试](https://www.bilibili.com/toy/Suxinhao_XHTI_stagetest/index.html)。
- 标题页改成简洁的故事入口，不再把版本号、存档机制、人物论断和长段玩法说明堆在首屏。

## 视觉与字体

- 标题和大号强调文字使用“可画乐融融”，小型 UI 使用“可画奶糖体”。源字体放在 `resources/raw/travelling-bingo/fonts/`，网页仅发布字符子集化的 WOFF2。
- 房间以用户提供的竖版 `image-1` 为唯一构图母版做直接高清精修，严格保留原有竖版比例、绘画风格、两层结构、树冠、人物与兔子装饰以及全部家具位置，不改变构图方向或重新布置。源母版为 1098 × 1433，网页发布 768 × 1002 与 1098 × 1433 两档 WebP。
- 饼狗继续保持短圆团子比例，新增室内走路和冰箱、电脑、衣架、睡眠、拒绝等状态。

## 本地启动

Windows 下双击仓库根目录的 `启动旅行饼狗.cmd`。脚本会检查 Node.js 24 与 npm 11，并在依赖目录、锁标记缺失或 `package-lock.json` 变化时同步依赖，然后打开：

```text
http://localhost:5173/AllForSUXINHAO/TravellingBingo/
```

若端口被占用、环境缺失或安装失败，脚本会保留窗口并显示中文原因。

需要清理本地构建与测试产物时，先运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/maintenance/clean-workspace.ps1 -WhatIf
```

去掉 `-WhatIf` 才会正式清理。脚本只处理六个明确的可重建目录，不处理依赖、研究资料、素材或字体。
