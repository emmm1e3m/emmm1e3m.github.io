# 旅行饼狗交付说明

## 本轮目标

本轮把 Demo 升级为 V3：房间在待机时回到视觉主体，五种需要等待的活动共享一套可恢复、可取消的读条规则；用户名、陪伴天数、好友图鉴、电子琴和 B 站视频收藏共同进入长期游玩循环。

## 已冻结的 V3 规则

- 游戏位置保持为 `/AllForSUXINHAO/TravellingBingo/`，`AllForSUXINHAO/` 只容纳这一个游戏。
- 新旅程先填写用户名。顶栏显示“{用户名}陪伴饼狗已经 N 天”；只有领取一件读条活动的结果才增加一天，浏览房间或打开面板不会增加天数。
- 旅行、刷播、冲热、弹琴和睡觉都是读条活动，默认时长均为 112 秒。开始前必须在信息栏二次确认。
- 五类读条都可以从房间左下角取消。取消后不进入下一天，已经在开始时消耗的补给或幸运苹果不返还；无消耗的弹琴和睡觉则只结束本次活动。
- 进行中活动的 `startedAt`、`endsAt` 和奖励计划随 `.bingo` 保存。读档继续按原来的绝对 `endsAt` 判断完成，之后修改默认时长也不会延长已经开始的活动。
- 睡觉完成后增加一天、获得 1🍎、刷新活动意愿，并播放整个场景由暗到亮的日夜交替。饼狗睡觉时严格位于床上。
- 饼狗对旅行、电脑和音乐分别有活动意愿；刷播与冲热共享电脑意愿。它不想做的按钮仍然可见但变暗，点击后给出拒绝原因且不扣资源。DEBUG 不会强制所有意愿都为愿意。
- 房间始终有三条 Bingo 小任务。每条完成时立即获得 🍎；三条都完成后播放 `Bingo!` 反馈并自动刷新三条新任务。
- 向冰箱中补充道具负责消耗 🍎；按钮金额显示为 `3🍎` 这类形式。游玩界面不显示“苹果只在游戏里流通”等系统外叙述。

## 收藏、好友与概率

- 明信片基础概率为 65%，百万直拍为 40%，全站第一为 10%，旅行遇见朋友为 20%，弹琴遇见已认识朋友为 20%。这些基线与 DEBUG 覆盖统一由领域配置管理。
- 旅行按“先朋友、后明信片”的顺序判定。遇见朋友时，本次不会同时出现明信片；朋友会赠送一种适合出行或活动的道具。没有遇见朋友时，才按明信片概率继续判定。
- 弹琴结束时只会从已经认识的朋友中选择来访者。来访朋友会赠送固定的 2–4🍎；尚未认识任何朋友时不会凭空出现音乐来访者。
- 明信片和百万直拍只从当前未拥有集合中随机选取。全站第一不乱序，按 `chronology` 从 Dynamite 开始由旧到新逐个获得，当前目录最新项是 POWER。三类收藏都不会再次选中已拥有项。
- “饼狗的收藏墙”只显示已经拥有的内容。明信片、百万直拍、全站第一和“好朋友们”都在首次获得或遇见后才解锁；没有灰色占位，也不会提前泄露分类。
- 收藏推进只依赖存档中的已拥有 ID 与首获时间，好友图鉴只保存已遇见好友记录。存档不写入目录总数、“下一项”索引或分类解锁列表，所以以后扩充目录时旧档会自然识别新内容。
- 当前目录已有 100 张来自 Bilibili Toy 归档的明信片、30 张百万直拍、8 项全站第一和 5 位好友。`Survivors` 已换成正确的红白纪念海报。
- 百万直拍与全站第一的每张海报都关联一条静态保存的 BVID、标题、作者和发布时间；详情页使用 B 站内嵌播放器。唱片机从百万直拍收藏夹锁定的最新页曲目中选择播放，不在运行时抓取收藏夹。

## 房间与交互契约

- 顶栏、房间和信息栏使用同一个外层网格：房间左边与顶栏左边对齐，信息栏右边与顶栏右边对齐；顶栏到内容、房间到信息栏使用同一组紧凑间距。
- 待机时点击房间空白区域会收起信息栏，房屋横向展开到两侧；点击具体设施时，房屋收窄并向左对齐，为信息栏让出空间。
- 设施热点使用“床铺”“电脑”“电子琴”等文字按钮，并使用可画乐融融。整体正文与小型 UI 使用可画奶糖体，字号不得回到首版的偏小状态。
- 顶栏中央固定显示“今天也要好好吃苹果”，字号适当放大；右侧显示陪伴天数、`N🍎`、`🖼️` 收藏入口和 DEBUG 入口。
- 右上角问号介绍房间设施、读条规则以及 🍎 的主要获得与花费方式。
- 点击设施后饼狗移动到对应家具位置；旅行时房间中不显示饼狗，睡觉在床上，刷播与冲热在电脑前，弹琴在电子琴旁。饼狗正在使用的设施热点不遮挡角色。
- 两个八度的电子琴在弹琴读条期间仍可自由演奏；每个琴键可用鼠标、触摸或键盘操作。
- “奇迹饼狗”正文为“什么样的搭配最合适呢？”，按钮在新窗口打开 [Bilibili 舞台测试](https://www.bilibili.com/toy/Suxinhao_XHTI_stagetest/index.html)。
- 刷播说明使用“在电脑前好好陪伴，加速百万直拍的达成”，不再显示“饼狗忙完会在这里等你。”。
- 活动结果、收藏详情和好友相遇对话框应隐藏浏览器式滚动条；内容超出时仍要支持滚轮、触摸和键盘滚动，关闭按钮保持可达。

## 已确认落地的底层与素材

- V3 领域状态已经包含用户名、陪伴天数、好友记录、五类读条、取消动作与两条独立好友概率。
- V1、V2 存档均先校验原文件摘要再迁移到 V3；进行中活动保留原 `startedAt`、`endsAt` 和奖励快照。新导出只写 V3 业务 payload。
- 浏览器收到下载请求后仍保留当前游戏；只有玩家确认文件已经保存且期间没有新进度，离开或 PWA 更新才会继续。跨标签 Service Worker 接管也不能绕过这道保护。
- 100 张明信片、5 位好友、30 张百万直拍、8 项全站第一和静态 B 站视频目录已经生成到公开内容数据中。
- `Survivors` 的公开 480 / 800 WebP 已从正确原图重建。

界面、响应式布局、离线外壳、电子琴、好友/视频收藏与存档保护已完成本地自动化验收；最终 Pages 上线状态仍以本轮发布后的在线复核为准。

## 本地启动

Windows 下双击仓库根目录的 `启动旅行饼狗.cmd`。脚本会检查 Node.js 24 与 npm 11，并在依赖目录、锁标记缺失或 `package-lock.json` 变化时同步依赖，然后打开：

```text
http://localhost:5173/AllForSUXINHAO/TravellingBingo/
```

若端口被占用、环境缺失或安装失败，脚本会保留窗口并显示中文原因。

需要清理本地构建与测试产物时，先运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/maintenance/clean-workspace.ps1 -WhatIf
```

去掉 `-WhatIf` 才会正式清理。脚本只处理六个明确的可重建目录，不处理依赖、研究资料、素材或字体。
