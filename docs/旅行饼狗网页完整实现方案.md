## 1. 产品定义

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。核心体验是在一间有生活感的房间里陪饼狗度过日常、尊重它当下的意愿，并在旅行、刷播、冲热、弹琴和睡觉中累积陪伴天数、收藏与好友回忆。

产品原则：

- 房间是主体，面板是辅助；待机时信息栏主动让位给房屋。
- 饼狗不是无条件执行指令的按钮；它有旅行、电脑和音乐三组活动意愿。
- 有读条的行动共享同一套确认、绝对时间、取消和领取规则。
- 🍎 的获得与花费有清楚来源；同一消耗流程不设计成即时返还同一货币。
- 收藏以“第一次看见”为惊喜，不在开局暴露全部分类、总数或灰色空位。
- 好友是可持续积累的图鉴，不是一次性的结果文案。
- UI 只描述饼狗的世界和当前行动，不出现“货币只在游戏里流通”等元叙述。
- 明信片、百万直拍与全站第一使用用户确认授权的真实素材；生成式图像只用于房间、饼狗和好友角色资源。

## 2. 实现状态口径

本文同时承担实现设计与验收合同。表达约定如下：

- “已实现”只用于已经能在代码、测试或生成目录中定位的事实。
- “应”“必须”表示本轮最终界面和浏览器流程仍需满足的冻结契约。
- 并发中的 UI、响应式和 Pages 结果只有在最终质量门禁与真实浏览器验证通过后，才可改写为“已验收”。

目前已经落地的底层事实：

- `GameStateV3`、五类读条、取消动作、用户名、陪伴天数、好友记录和 V1/V2 → V3 迁移已有领域与持久化实现。
- 100 张明信片、30 张百万直拍、8 项全站第一、5 位好友和静态 B 站视频目录已经生成到公开数据。
- `Survivors` 已使用正确的红白纪念海报重建公开 WebP。

## 3. 运行与发布边界

- 游戏不需要游戏账号、游戏后端、数据库、排行榜、真实支付、广告或用户跟踪。
- `.bingo` 是玩家可下载和重新导入的权威存档；PWA 缓存不是存档。
- 首次在线访问并缓存应用外壳后，标题页、房间、计时、领奖、导入和导出应可离线工作。B 站 iframe 与未访问过的高清内容不承诺离线可用。
- GitHub Pages 根首页仅提供进入按钮。Vite `base`、PWA `scope`、manifest `id/start_url` 全部固定为 `/AllForSUXINHAO/TravellingBingo/`。
- `AllForSUXINHAO/` 只放置 `TravellingBingo/`。Pages 仅上传组装后的 `_site/`，不公开 `docs/`、`research/`、`resources/raw/`、源码、抓取脚本或浏览器状态。
- 运行时不调用 B 站收藏夹 API，也不跨域请求微博图片；收藏元数据在构建期固化为同源 JSON。

## 4. 信息架构与主流程

```text
根首页入口
  → 标题页
  → 输入用户名并开始新旅程 / 选择 .bingo
  → 存档摘要确认
  → 饼狗的房间（默认待机展开）
      ├→ 点空白 / Escape → 收起信息栏
      ├→ 点饼狗 → 查看意愿与行动
      ├→ 点设施 → 房屋收窄 + 信息栏二次确认
      ├→ 三条 Bingo 小任务 → 获得 🍎 → 刷新任务板
      ├→ 冰箱 → 使用 🍎 补充道具
      ├→ 旅行 / 刷播 / 冲热 / 弹琴 / 睡觉
      │    → 112 秒绝对时间读条
      │    ├→ 中途取消：不计天数、不返还资源
      │    └→ 领取结果：陪伴天数 +1
      ├→ 电子琴 → 读条期间仍可演奏两个八度
      ├→ 唱片机 → 静态曲目目录 + B 站内嵌播放器
      ├→ 饼狗的收藏墙 → 收藏 / 好朋友们 / 视频详情
      └→ 奇迹饼狗 → 新窗口舞台测试
  → 离开房间
  → 下载最新 .bingo
  → 返回标题页
```

## 5. 标题页与用户名

### 5.1 首屏

- 短标题“旅行饼狗”。
- 一句有情境感的短引导，不把玩法说明和内部版本号堆在首屏。
- 新旅程先输入用户名，再激活“开始新旅程”。
- 用户名去除首尾空白，接受 1–16 个非空 Unicode 字符；不合格时在输入框附近给出说明。
- 次操作为读取 `.bingo`。
- 非官方、非商业粉丝作品声明放在低干扰页脚。

### 5.2 存档导入

- 文件选择后先校验，不立即覆盖当前状态。
- 预览显示导出时间、用户名、陪伴天数、`N🍎`、饼狗状态与是否有进行中活动。
- 文件名和错误文本始终按纯文本渲染。
- 只有点击“进入这次旅程”后，才采用已经校验与迁移的 V3 状态。

### 5.3 DEBUG 入口

标题连续激活五次后可触发隐藏 DEBUG 入口，密码为 `TravellingBingo`。它只是隐藏交互，不是安全边界；普通首屏不展示调试能力。

## 6. 视觉、字体与文案

### 6.1 字体

| 用途                                   | 字体       | 公开文件                              |
| -------------------------------------- | ---------- | ------------------------------------- |
| 游戏标题、页面大标、房间设施、收藏分类 | 可画乐融融 | `assets/fonts/kehua-lerongrong.woff2` |
| 正文、按钮、任务、日期与小型 UI        | 可画奶糖体 | `assets/fonts/kehua-naitang.woff2`    |

源字体位于 `resources/raw/travelling-bingo/fonts/`。构建只发布项目字符子集 WOFF2，并提供合理的系统回退字体。日期中的“月”等汉字必须包含在子集与对应 font-family 中，不能局部退回浏览器默认字体。

整体字号以可读为先：正文、意愿、任务和按钮不得沿用首版偏小尺寸。标题字不应用到长正文。

### 6.2 配色

```text
奶油背景    #FFF4E4
暖象牙面板  #F9E8CF
苹果红主色  #C43B4A
柔杏色强调  #E8A08A
栗棕正文    #5C3B33
蜂蜜金提示  #D7A044
浅粉桃装饰  #F3C7BD
```

绿色只用于植物和头顶小芽等自然点缀，不作为大面积面板、按钮或完成态主色。上述 token 只约束网页 UI；房间严格保留用户 `image-1` 的原有色彩与手绘质感。

### 6.3 货币与按钮

- 所有可见货币数值统一写为 `N🍎`；例如补给按钮写 `3🍎`，结果写“朋友送来 3🍎”。
- 不显示“X 个苹果”“补充·X个苹果”“带回苹果”或“苹果只在游戏里流通”。“苹果”一词仍可用于角色口味、道具名称和顶栏固定句“今天也要好好吃苹果”。
- 冰箱标题使用“为冰箱补充”或“向冰箱中补充道具”。
- 衣架正文严格为“什么样的搭配最合适呢？”。
- 刷播说明严格为“在电脑前好好陪伴，加速百万直拍的达成”；不显示“饼狗忙完会在这里等你。”。
- 房间热点用“床铺”“电脑”“衣架”“电子琴”等文字，不用抽象图标要求玩家猜测。
- 主、次、文本按钮共享圆角、内边距、焦点圈和按压反馈；触控目标至少 `44 × 44 CSS px`。
- 不使用原生业务 `<select>`；短选项用分段文字按钮，概率调节用可键盘操作的滑杆和数值回显。

## 7. 房间布局与待机交互

### 7.1 桌面网格

- 顶栏、房间舞台和信息栏共用同一个页面容器与左右 inset。
- 房间左边严格对齐顶栏左边，信息栏右边严格对齐顶栏右边。
- 顶栏到内容的纵向 gap 与房间到信息栏的横向 gap 使用同一 token；该 token 约为旧横向间距的一半。页面外侧 inset 不因“间距减半”而被误缩小。
- 房间和信息栏顶边对齐。
- 顶栏中心文字“今天也要 / 好好吃苹果”保持真正居中且比首版更大；右侧依次容纳陪伴天数、`N🍎`、`🖼️` 与 DEBUG。
- 陪伴文字为“{displayName}陪伴饼狗已经 N 天”。天数不和任意点击绑定。

### 7.2 待机与展开

- `PanelId = null` 是默认待机状态：信息栏不占位，房屋横向铺展到页面两侧。
- 点击设施或饼狗后，房屋平滑收窄并向左对齐，右侧信息栏出现。
- 点击没有热点的房间空白、信息栏外遮罩或按 Escape，回到待机状态。
- 热点、饼狗、钢琴键、播放器和对话框内部事件必须阻止冒泡，不能误收起当前面板。
- 动画只改变布局与透明度，不拉伸房间图片；`prefers-reduced-motion` 下直接切换或缩短过渡。

### 7.3 手机布局

- 顶栏只保留必要操作，房间先于信息内容展示。
- 房间热点不能在窄屏消失；可以缩短文字或让信息栏成为全宽抽屉。
- 对话框内容区独立滚动，关闭和取消始终可达。
- 可隐藏可见滚动条，但必须保留滚轮、触摸、方向键和 PageUp/PageDown 的滚动能力。

### 7.4 房间母版

唯一生产母版：

```text
resources/raw/travelling-bingo/generated/chan-chan-house-v2.png
```

公开派生图：

```text
public/assets/game/chan-chan-house-v2-768.webp    # 768 × 1002
public/assets/game/chan-chan-house-v2-1098.webp   # 1098 × 1433
```

母版以 `resources/raw/travelling-bingo/references/outline/image-1.png` 为唯一构图参考，只提升清晰度、边缘稳定性与小纹理。不得改变竖版构图、两层结构、树冠、人物、兔子、床铺、电脑、衣架、电子琴、唱片机、冰箱、收藏墙和房门的位置关系。

## 8. 饼狗锚点与状态

- 房间热点与角色位置使用同一组相对锚点配置，避免设施按钮和角色坐标各自漂移。
- 点击热点后饼狗移动到目标家具，再切换对应动作；当前设施热点隐藏，不能遮住角色。
- 旅行 `outside` 状态不渲染饼狗 DOM，不只是透明或移出可视区。
- 刷播和冲热位于电脑前；弹琴位于电子琴旁；睡觉位于上层床铺；旅行结束后位于房门。
- 睡觉锚点必须落在床垫范围，不能落在上下层连接走道。
- 饼狗自身是可聚焦按钮，Enter/Space 与点击都能打开意愿或活动状态。
- sprite 容器按当前帧精确裁剪，奖励弹窗顶部不得露出相邻帧残影；角色脚底基线和视觉尺寸在动作切换时稳定。

## 9. V3 持久领域状态

精确字段以 TypeScript 为准，核心形状如下：

```ts
interface GameStateV3 {
  schemaVersion: 3
  profile: {
    createdAt: number
    debug: boolean
    displayName: string
    companionDays: number
  }
  economy: { apples: number }
  inventory: Inventory
  collections: Record<string, CollectionEntry>
  friends: Partial<Record<FriendId, FriendEntry>>
  activeActivity: ActivityRun | null
  pet: {
    location: PetLocation
    preferences: Record<'travel' | 'computer' | 'music', boolean>
    tired: boolean
    restCount: number
  }
  tasks: TaskBoard
  gameBalance: GameBalance
  statistics: GameStatistics
  random: {
    seed: string
    sequences: {
      reward: number
      tasks: number
      preferences: number
    }
  }
}
```

`ActivityRun` 必须保存：

```ts
interface ActivityRun {
  runId: string
  kind: 'travel' | 'stream' | 'trend' | 'music' | 'rest'
  startedAt: number
  endsAt: number
  rewardSeed: string
  rewardPlan: RewardPlan
  supplyId: ItemId | null
  usedLuckyApple: boolean
}
```

当前打开哪个面板、对话框焦点、电子琴正在按哪些键、动画帧和日夜转场进度属于 UI 瞬时状态，不写入 `.bingo`。

### 9.1 目录不是存档

收藏目录、好友目录和视频目录是当前版本运行时输入。存档不保存：

- 收藏分类总数或总收藏数；
- 全站第一的“下一项”索引；
- 分类解锁数组；
- 好友总数；
- B 站视频元数据副本。

完成度、下一个全站第一、可见分类和好友卡都由“当前目录 + 存档拥有记录”即时派生。目录新增项目时，旧存档不需要重置。

## 10. 五类读条、陪伴天数与取消

### 10.1 基线

```ts
BASE_ACTIVITY_DURATION_MS = 112_000
```

| 活动 | 入口   | 意愿     | 补给       | 位置     | 主要结果                |
| ---- | ------ | -------- | ---------- | -------- | ----------------------- |
| 旅行 | 房门   | 旅行     | 旅行便当   | 房外     | 朋友道具或明信片        |
| 刷播 | 电脑   | 电脑     | 信号耳机   | 电脑前   | 百万直拍                |
| 冲热 | 电脑   | 电脑     | 热度工具箱 | 电脑前   | 全站第一                |
| 弹琴 | 电子琴 | 音乐     | 无         | 电子琴旁 | 已认识好友可能赠 2–4🍎  |
| 睡觉 | 床铺   | 始终允许 | 无         | 床上     | 1🍎、刷新意愿、日夜转场 |

- 五类开始前都必须在信息栏二次确认，确认文本说明时长、补给、可能结果和取消语义。
- `endsAt - 1 ms` 仍是进行中；`endsAt` 起可领取。
- 每次成功领取当前 `runId` 的结果，`companionDays` 恰好增加 1。
- 页面每秒刷新视图，并在 `focus` 与 `visibilitychange` 后立即按系统时间重算；长 `setTimeout` 不是权威时钟。
- 活动开始时写入完整奖励计划，导出、导入或 DEBUG 调参后不重抽。

### 10.2 取消

- 左下角在活动 running 与 ready 阶段都提供取消/返回操作。
- 取消必须携带当前 `runId`，防止旧按钮清除新活动。
- 成功取消后 `activeActivity = null`，不增加陪伴天数，不发放收藏、好友或 🍎。
- 已经消耗的补给与幸运苹果不返还；开始活动时推进的奖励随机序列也不回滚。
- 取消睡觉或弹琴没有资源损失，但仍不计一天。
- 取消确认应明确“不返还已经用掉的补给”，不得在取消后再默默退款。

## 11. 活动意愿与睡眠

- 意愿维度为旅行、电脑、音乐；刷播与冲热共享电脑意愿。
- 每轮至少保留一组可做的非睡眠活动。
- 不愿意的活动按钮视觉变淡但仍可聚焦、可点击；点击后显示“现在不太想做”的世界内文案，不扣库存、不写活动、不推进随机序列。
- DEBUG 的概率与时长覆盖不能顺带把所有意愿改为 `true`。
- 睡觉不受意愿拒绝，但有其他活动时不能再开始。
- 睡觉领取后：`companionDays + 1`、`economy.apples + 1`、`restCount + 1`、清除疲劳并生成新意愿。
- UI 播放整场景由亮到暗、短暂停留、再变亮的转场；`prefers-reduced-motion` 下缩短为柔和明暗切换。

## 12. Bingo 任务与 🍎 经济

### 12.1 任务板

- 新游戏与旧档迁移后都保持恰好三条任务。
- 同一板不重复模板，尽量不重复触发组，并排除当前不可能完成的条件任务。
- 单条完成立即发放任务快照中的 🍎，不需要另点领取。
- 三条都完成时触发一次 `Bingo!`，领域层生成新板；完成旧板的事件不继续推进新板。
- 任务实例保存目标与奖励快照，之后更新任务库不改变已经签发的任务。
- 购买补给、开始活动、取消活动和领取结果不作为消费后返现任务。

可验证任务事件包括：问候饼狗、打开饼狗菜单、走访房间、查看收藏、弹奏音符、打开唱片机、打开收藏播放器与舞台测试。

### 12.2 经济流

```text
无消耗的 Bingo 小任务 ─→ 🍎
睡觉完整读条 ─────────→ 1🍎
弹琴完整读条 + 已认识好友来访 ─→ 2–4🍎
🍎 ──────────────────→ 为冰箱补充道具 / 明确的意愿鼓励
道具 ─────────────────→ 旅行 / 刷播 / 冲热
```

旅行好友只赠道具，不赠 🍎，避免“用 🍎 准备旅行后又在同一流程直接返还 🍎”。收藏不能兑换 🍎。

### 12.3 补给基线

| 补给         | 基线花费 | 用途                               |
| ------------ | -------: | ---------------------------------- |
| 普通旅行便当 |      3🍎 | 启动一次旅行                       |
| 苹果旅行便当 |      5🍎 | 启动旅行，遇友概率增加 15 个百分点 |
| 信号耳机     |      4🍎 | 启动一次刷播                       |
| 热度工具箱   |      7🍎 | 启动一次冲热                       |
| 幸运苹果     |      6🍎 | 当次对应收藏概率增加 20 个百分点   |

界面列表只显示 `3🍎`、`5🍎` 等金额，不在按钮里重复“补充”“个苹果”。价格与概率来自统一领域配置，不在 React 组件中另写常量。

## 13. 奖励顺序与概率

```ts
export const DEFAULT_GAME_BALANCE = {
  activityDurationMs: 112_000,
  probabilities: {
    postcard: 0.65,
    millionShot: 0.4,
    siteFirst: 0.1,
    travelFriend: 0.2,
    musicFriend: 0.2,
  },
} as const
```

统一规则：

- 所有概率判定为 `roll < chance`；0 永不命中，1 必定命中。
- 幸运苹果增加 `0.20`，苹果旅行便当增加 `0.15`，均按 `Math.min(1, base + bonus)` 封顶。
- 基础收藏概率已经为 1 或对应分类已经集齐时，幸运苹果不可使用且不扣库存。
- 全站第一基础概率严格为 10%，没有保底；默认使用幸运苹果时为 30%。
- DEBUG 分别调整明信片、百万直拍、全站第一、旅行遇友和音乐遇友；覆盖只影响之后开始的活动。
- 不维护预制全收集档；“一键全收集”按当前三类收藏目录即时写入拥有记录，不伪造未来目录总数。

### 13.1 旅行互斥

旅行必须严格按以下顺序计划结果：

1. 先判 `travelFriend`，苹果旅行便当只在这里增加 15 个百分点。
2. 命中后从五位朋友中选择，写入 `friendId` 与固定 `giftItemId`。
3. 已命中朋友时立即停止，不再判明信片。
4. 没有朋友时，才按 `postcard`（默认 65%）判定明信片。
5. 命中明信片后，从当前未拥有项中随机选择。

因此新开始的 V3 旅行不可能同时出现朋友和明信片。迁移自 V2 的已签发旧活动如果历史上同时包含两者，则保留原快照以保证存档忠实性。

### 13.2 音乐好友

- 弹琴先读取活动开始时已经认识的好友集合。
- 集合为空时不做来访判定，不能凭空解锁好友。
- 命中 `musicFriend` 后从已认识好友中选择一位。
- 赠礼按身份固定为 2–4🍎，不额外消耗另一条随机序列。
- 领奖更新好友的最近见面时间、见面次数和累计赠送 🍎。

### 13.3 结果文案

- 全站第一命中：“全站第一！”
- 全站第一未命中：“很遗憾没能拿到全站第一”。
- 明信片结果直接描述“旅途中遇见一份风景”，不显示泛化的“活动完成”。
- 刷播未掉落时描述本次陪伴状态，不写“这次没有海报”。
- 好友结果展示对应角色图、姓名和本次赠礼。
- 奖励主按钮使用“收好这份回忆”等世界内文案；首次获得分类时另有分类解锁反馈。

## 18. `.bingo` 存档与迁移

### 18.1 外层格式

- UTF-8 JSON，扩展名 `.bingo`，MIME `application/octet-stream`。
- 外层包含格式标识、封套 schemaVersion、`gameVersion`、导出时间、业务 payload 与 SHA-256 摘要。
- 最大 1 MiB，Zod 严格校验；未知顶层字段拒绝。
- 必须先针对原始 payload 验证摘要，再执行 V1/V2 → V3 迁移、平衡配置规范化和目录协调。
- SHA-256 只用于发现文件损坏或误改，不是密钥签名。

### 18.2 V3 导出

- 新导出只写 `GameStateV3` 业务 payload，当前 `gameVersion` 为 `0.3.0-demo.1`。
- 用户名、陪伴天数、好友、任务、意愿、调试平衡、随机序列和活动完整往返。
- 进行中活动原样保存 `startedAt / endsAt / rewardSeed / rewardPlan`。
- 普通文件名：`travelling-bingo-YYYYMMDD-HHmmss.bingo`；DEBUG 在扩展名前附加 `-debug`。
- 有未导出变更时注册 `beforeunload`；关闭浏览器不承诺自动下载。“离开饼狗的房间”先请求下载，只有玩家明确确认文件已经保存且期间没有新进度时才回标题页。
- PWA 更新与跨标签 Service Worker 接管使用同一保护：未确认保存的内存进度存在时不得自动刷新页面。

### 18.3 V1/V2 迁移

- V1、V2 分别用严格历史 schema 解析，不允许把未知对象猜成旧存档。
- 迁移保留余额、库存、收藏、首获时间、seed、可恢复任务信息和进行中活动结果。
- 历史用户名缺失时设为“你”；`companionDays` 由历史旅行、刷播和冲热的 `claimed` 计数之和推导，并限制在安全上限内。
- 旧活动保留原 `startedAt` 和绝对 `endsAt`；后续默认时长变化只影响新开始的活动。
- V2 的 `friend` 概率迁移到旅行好友概率；音乐好友使用 V3 默认值。
- V2 的旅行/刷播/冲热意愿映射为旅行与共享电脑意愿；非疲劳旧档默认愿意弹琴，已疲劳旧档必须先睡觉。
- 历史进行中旅行如果同时计划朋友和收藏，迁移保留二者；只有新开始 V3 旅行使用互斥规则。
- 旧存档导入后再导出只写 V3，迁移补偿或兼容逻辑不能在下次导入重复执行。

### 18.4 目录扩充兼容

- 存档不写目录总数、分类解锁或全站第一指针。
- 导入时仅要求拥有 ID 仍存在于当前目录；新增 ID 自动成为未拥有候选。
- 旧档存在的进行中奖励 ID 必须继续可领取；目录协调不得因为已经拥有或新增内容而重抽其奖励。

## 22. PWA、性能、安全与可访问性

### 22.1 缓存

- App Shell、字体子集、小尺寸房间、好友卡、JSON 目录和合理尺寸的收藏缩略图进入预缓存。
- 高清收藏图按需缓存，不把全部高清图库压进首次下载。
- 固定文件名必须有内容 revision；预缓存 URL 唯一且全部在公开白名单内。
- 新 Service Worker 可用时提示更新，不在未导出变更时自动刷新。
- 第三方 B 站 iframe 不进入 Workbox 预缓存。

### 22.2 安全与隐私

- 不加入统计、跟踪、指纹或第三方广告脚本。
- GitHub PAT、微博 Cookie、浏览器登录态和抓取请求头不进入仓库、构建产物或文档。
- 外链使用 `noopener noreferrer`；弹窗或 iframe 失败时提供安全备用链接。
- 导入对象经过严格 schema 重建白名单字段；不可信文本不传给 `innerHTML`。
- 视频目录只保存公开元数据，不保存账户凭证。

### 22.3 可访问性

- 对话框打开时移入焦点、限定焦点、Escape 关闭并隔离背景；关闭后恢复到仍存在的触发按钮。
- 奖励关闭后不能把焦点送回已经隐藏的设施热点。
- 背景点击支持指针和触摸，不只监听鼠标。
- 颜色不是任务完成、意愿拒绝或分类解锁的唯一信息。
- 电子琴键有音名标签、键盘映射和按下状态。
- 隐藏滚动条不等于禁止滚动。
- 所有动画遵循 `prefers-reduced-motion`，不自动播放有声音内容。

## 24. 验收清单

### 24.1 领域、时间与迁移

- 新游戏生成 `schemaVersion: 3`，用户名规范化，陪伴天数为 0，好友图鉴为空。
- 五类新活动默认 `endsAt = startedAt + 112_000`。
- `endsAt - 1` 不可领取，`endsAt` 可领取；成功领取只增加一天。
- running 与 ready 均可取消；取消不增加天数、不返还补给、不发奖。
- 睡觉领取获得 1🍎、刷新意愿并把角色位置留在床铺。
