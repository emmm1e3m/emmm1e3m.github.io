# 旅行饼狗网页完整实现方案

> 原始需求：[旅行饼狗开发纲要](specs/旅行饼狗开发纲要.md)
>
> 固定路径：`https://emmm1e3m.github.io/AllForSUXINHAO/TravellingBingo/`

## 1. 产品定义

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。玩家在铲铲饼屋陪饼狗旅行、刷播、冲热、弹琴和睡觉，通过读条、Bingo 小任务、收藏与好友积累陪伴回忆；也可以切换到现实生活维度，用苹果钟和待办让游戏陪伴真实工作与学习。

产品原则：

- 房间是视觉主体，信息栏只解释当前语境与可执行动作。
- 饼狗有自己的旅行、电脑和音乐意愿；拒绝是可见状态，不是隐藏入口。
- 五类饼屋读条共享二次确认、绝对时间、取消、领取和存档恢复规则；现实苹果钟使用独立的绝对时间完成流程。
- 🍎 的获得与花费都有明确来源；金额一律显示为 `N🍎`。
- 收藏与好友以第一次相遇为惊喜，不提前展示灰色占位、未解锁分类或永久总数。
- 游戏状态与第三方播放器、浏览器通知等外部能力严格分层；不可观测的外部状态不得被伪装成成功。
- `.bingo` 由玩家自己保管，不上传、不登录。

## 2. 运行与公开边界

- 游戏固定部署在 `/AllForSUXINHAO/TravellingBingo/`；根首页只提供入口。
- Vite `base`、PWA `id`、`start_url`、`scope` 与导航回退均使用该子路径。
- 游戏不需要后端、数据库、排行榜、支付、广告、统计或用户跟踪。
- 首次在线访问并缓存应用外壳后，标题页、房间、计时、领奖和存档可离线使用；第三方 B 站 iframe 与未缓存高清图不承诺离线可用。
- 运行时不调用 B 站收藏夹 API，也不跨域抓取微博图片。内容目录在构建期固化为同源 JSON。
- Pages 只上传隔离组装的 `_site/`，不公开 `docs/`、`research/`、`resources/raw/`、源码、浏览器状态或抓取凭证。

## 3. 主流程

```text
根首页入口
  → 标题页
      ├→ 检查更新
      ├→ 有缓存时“继续”
      ├→ “全新旅程” → 输入系统称呼并开始
      └→ “本地存档” → 选择 .bingo → 摘要预览 → 确认导入
  → 铲铲饼屋
      ├→ 房间空白 → 当前任务与意愿概览
      ├→ 设施 → 对应信息栏
      ├→ 读条活动 → 二次确认 → running / ready
      │    ├→ ↩️ 取消：不计天、不退款、不发奖
      │    ├→ 速度魔法：立即 ready
      │    └→ 领取：陪伴天数 +1
      ├→ 收藏墙 → 收藏 / 好朋友 / 视频详情
      ├→ 唱片机 → 持久播放器
      ├→ 电子琴 → 四排琴键
      ├→ ℹ️ → 简洁的“铲铲饼屋的小纸条”
      └→ 右下维度按钮
           ├→ 游戏维度
           └→ 现实维度 → 刷播 / 冲热（开发中） / 工作
                ├→ 刷播：直接打开 B 站视频页并循环调度
                ├→ 苹果钟完成专注与休息整轮：陪伴天数 +1
                └→ 返回结算：只结算 🍎，不加天
  → 离开房间 → 浏览器缓存保留当前进度 → 返回标题页
```

## 4. 标题页、更新检查与称呼

- 标题页在存在缓存时显示“继续”，并始终提供“全新旅程”“本地存档”和“检查更新”。首次进入或从旅程返回标题页时自动检查一次，同一次停留不因重绘重复触发，按钮仍可手动再查。
- 称呼去除首尾空白，接受 1–16 个非空 Unicode 字符；不合格时在输入框附近说明。
- 导入预览显示文件名、导出时间、游戏版本、称呼、陪伴天数、`N🍎`、收藏数量和当前活动。
- 文件选择只创建待确认预览，不立即覆盖内存状态。
- 自动与手动“检查更新”共用当前 Service Worker registration 的 `update()`、检查状态和结果提示；没有 Service Worker、尚未注册或网络失败时显示相应状态。
- 检查结果使用临时提示，不作为固定页面元素；检测到新 Service Worker 时自动下载当前缓存档，再提供安装更新。
- 连续激活标题五次后可输入 `TravellingBingo` 解锁 DEBUG；它是隐藏入口，不是安全边界。

## 5. 视觉、字体与通用文案

### 5.1 字体

| 用途                                   | 字体       | 公开文件                              |
| -------------------------------------- | ---------- | ------------------------------------- |
| 游戏标题、页面大标、房间设施、收藏分类 | 可画乐融融 | `assets/fonts/kehua-lerongrong.woff2` |
| 正文、按钮、任务、日期与小型 UI        | 可画奶糖体 | `assets/fonts/kehua-naitang.woff2`    |

字体源位于 `resources/raw/travelling-bingo/fonts/`，公开页面保持上述路径和 CSS 字体族不变，发布“《现代汉语常用字表》2500 个常用字 + ASCII/中文标点 + 当前运行时表外用字”的 WOFF2。固定常用字表位于 `scripts/assets/data/modern-chinese-common-2500.txt`，构建和校验不依赖联网；新增普通常用字文案无需重建，新增表外字会由素材校验提示重建。日期中的“月”等汉字使用同一正文字体。

### 5.2 货币与固定文案

- 可见金额统一为 `N🍎`，例如 `3🍎`、`还差 2🍎`、`朋友送来 3🍎`。
- 不显示“X 个苹果”“补充·X个苹果”“按钮仍然可以按”等元叙述。
- “苹果”文字只用于角色口味、道具名称和“今天也要好好吃苹果”等自然语句。
- 冰箱标题为“补充道具”，不重复“为冰箱”。
- 衣架正文为“什么样的搭配最合适呢？”。
- 刷播说明为“在电脑前好好陪伴，加速百万直拍的达成。”。
- 空收藏墙文案为“惊喜会在相遇时悄悄出现。”。

### 5.3 控件

- 触控目标至少 `44 × 44 CSS px`，具备焦点圈、按压反馈和可理解的可访问名称。
- 房间设施用文字标签，不要求玩家猜抽象图标。
- 顶栏按性质分为左侧导航组与右侧运行/资源组，在可用宽度内自适应收缩且不互相遮挡；各 HUD 文字使用同一字号等级。
- 现实分钟、游客轮次/倒计时、活力、🍎、收藏墙和 DEBUG 均为可点击入口。现实分钟等同于返回游戏维度，活力等同于点击饼狗；旧“状态正常”不再显示。
- 信息栏顶行只保留语境标签；点击房间空白即可回到任务与意愿概览。
- 设施信息使用常规左对齐的读条卡层级，不复用大型居中结果页布局。
- `ℹ️` 按当前维度打开简洁说明；游戏维度不扩写成长篇设施或价格手册，现实维度需要说明苹果钟与 🍎 结算。

## 6. 房间母版与布局

### 6.1 唯一母版

```text
resources/raw/travelling-bingo/generated/chan-chan-house-master.png
```

母版为用户提供的 1098 × 1433 RGBA 原图。应用目录 `AllForSUXINHAO/TravellingBingo/` 下的公开派生图沿用兼容文件名：

```text
public/assets/game/chan-chan-house-v2-768.webp
public/assets/game/chan-chan-house-v2-1098.webp
```

处理只允许等比缩放和无损 WebP 编码；不得裁切、重绘、补画、改变构图或丢失透明通道。

### 6.2 桌面与移动布局

- 顶栏、房间和信息栏共享页面 inset。房间左侧与顶栏左侧对齐，信息栏右侧与顶栏右侧对齐。
- 房间到信息栏的横向 gap 与顶栏到内容的纵向 gap 使用同一紧凑 token。
- 纵向透明房图在横向房间卡内以 `contain` 居中完整显示，不拉伸、不裁切；母版以外的左右空间保持透明留白，不叠加内侧竖向底板。交互坐标相对实际图片舞台定位。
- 房屋与信息栏不做展开/收起动画；切换不同信息内容时使用轻量 keyed 入场动画。
- 手机上信息栏变为单列全宽内容；关闭、取消、维度切换和播放器控制必须留在视口或可滚动范围内。
- 隐藏滚动条不等于禁止滚动；滚轮、触摸、方向键和 PageUp/PageDown 仍要工作。

`ActivityRun` 保存 `runId`、种类、`startedAt`、`endsAt`、`rewardSeed`、完整 `rewardPlan`、补给和幸运苹果快照。当前面板、弹窗、琴键按下状态、奖励 UI、走路和日夜动画不写入存档。

### 7.1 目录不是存档

存档不保存：

- 收藏分类总数、总收藏数或完成百分比；
- 全站第一的“下一项”索引；
- 分类解锁数组；
- 好友总数与图片元数据；
- B 站标题、作者、海报或视频目录副本。

完成度、可见分类、下一项全站第一和播放器展示信息均由“当前目录 + 存档 ID”派生。目录增加项目时旧档无需重置。

## 8. `.bingo` 导入、导出与迁移

### 8.1 外层格式

- UTF-8 JSON，扩展名 `.bingo`，MIME `application/octet-stream`。
- 外层包含格式标识、封套版本、`gameVersion`、导出时间、业务 payload 与 SHA-256 摘要。
- 最大 1 MiB；未知字段由严格 Zod schema 拒绝。
- SHA-256 只用于发现损坏或误改，不是签名或加密。

### 8.2 V9 缓存与导出

- 日常成功动作同步写入版本化 `localStorage` 单槽缓存；缓存不可用时才注册离开提醒。
- 通过“全新旅程”或“本地存档”覆盖缓存前先下载旧缓存；首次获得新的全站第一或认识新朋友构成关键节点，每到关键节点、每隔三天、检测到网页更新时自动请求 `.bingo` 备份。
- 周期备份以 `lastPeriodicBackupRequestedAt ?? firstCachedAt` 为基准判断三天间隔；成功请求后更新周期备份时间，避免重复下载。
- 新导出只写 `schemaVersion: 9`，`gameVersion: 0.9.0-demo.1`。
- 用户名、天数、活动、任务、随机序列、收藏、好友、七种道具、魔法、现实、待办、苹果钟、播放器当前 BV/索引/循环模式、刷播累计轮次与最近 10 次任务记录，以及单个可选自测 BVID 与维度穿透开关完整往返；当前播放请求、暂停位置、画面展开状态、刷播窗口/iframe、间隔、限时和计时器不写入存档。
- 浏览器缓存 payload 迁移到 V9、平衡规范化、目录协调或暂停旧页面租约产生新对象时，同步写回 V9 payload、当前 `gameVersion` 与新的 `updatedAt`；`saveId`、`firstCachedAt`、周期备份时间及外层 `cacheVersion: 1` 保留。
- 正常文件名为 `travelling-bingo-YYYYMMDD-HHmmss.bingo`；DEBUG 在扩展名前加 `-debug`。
- 离开房间只返回标题页，不清除浏览器缓存；`.bingo` 继续作为显式备份与跨浏览器导入格式。

### 8.3 V1–V9 导入顺序

1. 先按文件原始 payload 校验摘要。
2. 用严格 V1–V9 schema 解析；V1–V8 历史 schema 保持冻结。
3. 逐代迁移到 V9；历史 V6→V7 仍将每条旧轮次如实迁为一条独立的 legacy 会话，不按时间猜测合并；V7→V8 初始化空自测 BVID 并关闭维度穿透；V8→V9 为现实停留增加累计有效时长和可暂停租约。
4. 规范非 DEBUG 状态未来活动的默认平衡。
5. 用当前目录协调可安全修复的旧引用。
6. 最终语义校验通过后才允许确认进入。

迁移不变量：

- 旧活动的 `startedAt`、`endsAt`、`rewardSeed`、`rewardPlan` 原样保留。
- 当前默认 10 秒只影响迁移之后新开始的活动。
- 历史用户名缺失时使用兼容称呼；陪伴天数由旧领取统计推导。
- V3 活动、好友与意愿字段保留；V4/V5 新字段使用安全初值，V1–V5 迁移到冻结 V6 时初始化空刷播历史，再迁到 V7 会话历史、V8 刷播设置，最后迁到 V9 现实计时租约。
- 旧 V8 活跃现实停留没有心跳证据，V8→V9 时保留停留身份与原进入时间，但令 `activeDurationMs = 0`、`leaseStartedAt = null`；不使用缓存更新时间猜测在线时长或补发离线奖励。
- 当前版本不允许退役的 `greet-bingo` 留在任务板；迁移按当前任务目录替换，并保持任务 PRNG 可重现。
- 任务板以 `completedAt` 记录最后一项完成时间；全完成板保留到下一次游戏日（陪伴日）推进再刷新。任一任务未完成时，跨游戏日原样继承任务与完成状态。
- 导入/缓存准备先迁移和规范，再确定性替换结构合法但已失去收藏前置条件的未完成任务槽位，最后做完整语义校验。已完成任务和仍可达任务保留原对象、进度与奖励快照；畸形、重复触发组、非法进度或非法 key 不经协调掩盖，最终拒绝。
- 已失效的苹果钟明信片背景可以清空；非法奖励组合、未知活动奖励或篡改时间必须拒绝，不能被协调步骤静默删除。

## 9. 五类读条与陪伴天数

```ts
BASE_ACTIVITY_DURATION_MS = 10_000
```

| 活动 | 入口     | 意愿     | 补给       | 位置     | 主要结果                   |
| ---- | -------- | -------- | ---------- | -------- | -------------------------- |
| 旅行 | 房门     | 旅行     | 旅行便当   | 房外     | 好友道具 + 2–4🍎，或明信片 |
| 刷播 | 二楼电脑 | 电脑     | 信号耳机   | 电脑前   | 百万直拍                   |
| 冲热 | 二楼电脑 | 电脑     | 热度工具箱 | 电脑前   | 全站第一                   |
| 弹琴 | 电子琴   | 音乐     | 无         | 电子琴前 | 已认识好友可能赠 4–8🍎     |
| 睡觉 | 床铺     | 始终允许 | 无         | 床上     | 1🍎、刷新意愿、日夜转场    |

- 五类开始前都显示时长、消耗、可能结果和取消语义。
- `endsAt - 1 ms` 仍是 running；从 `endsAt` 起为 ready。
- 计时视图每秒刷新，页面重新聚焦或可见时按系统时间重算；长 `setTimeout` 不是权威时钟。
- 每次成功领取当前 `runId`，`companionDays` 恰好 `+1`。
- 取消必须携带当前 `runId`，避免旧确认清除新任务。
- 取消不计天、不发奖、不退款，也不回滚开始活动时推进的奖励随机序列。
- 陪伴天数的另一来源是现实苹果钟完成专注与休息整轮；普通现实停留结算和待办不属于陪伴日。

## 10. 意愿、状态栏与两种魔法

- 意愿键为 `travel | computer | music`；刷播和冲热共享 `computer`。
- 每轮至少有一组非睡眠活动可做；睡觉领取后刷新意愿。
- 不愿意入口视觉变淡并带 `aria-disabled`，但保留点击以显示拒绝说明或活力魔法确认。
- 顶部状态栏按性质拆为左侧导航组与右侧运行/资源组，统一字号与控件样式并避免互相覆盖。状态使用低活力、中等活力、高活力或活力满满，不再显示笼统的“状态正常”。现实分钟、游客轮次/倒计时、活力、🍎、收藏墙和 DEBUG 都可点击跳转到对应页面或操作；不显示狗 emoji、守候音频或检查更新按钮，也不再套独立黑边胶囊。

### 10.1 瓶装速度魔法

- 道具 ID：`bottled-speed-magic`，价格 2🍎，emoji ⚡。
- 仅当前活动处于 running 时可用。
- 二次确认后消耗一瓶，将当前活动 `endsAt` 原子改为使用时间；奖励计划不变。
- 已 ready、runId 不匹配、没有道具或时间非法时不消耗。

## 12. 概率、好友与收藏顺序

```ts
DEFAULT_GAME_BALANCE = {
  activityDurationMs: 10_000,
  probabilities: {
    postcard: 0.65,
    millionShot: 0.3,
    siteFirst: 0.15,
    travelFriend: 0.1,
    musicFriend: 0.15,
  },
}
```

- 所有判定使用 `roll < chance`；0 永不命中，1 必定命中。
- 概率加成统一基于未增强基础值：`min(1, base + base × max(同类加成比例))`。同类加成只取最高比例，不在增强结果上继续复合。
- 苹果旅行便当只对当次旅行的 `travelFriend` 基础概率增加 100%，默认 0.1 → 0.2；幸运苹果只对当次活动对应的收藏基础概率增加 100%，不改变遇友概率。
- 已集齐分类，或基础概率为 0 / 1 时，不能浪费幸运苹果。

旅行顺序：

1. 判定 `travelFriend`。
2. 命中后从完整五人候选池选择好友，签发对应固定道具与按身份 2/3/4/3/2🍎 礼物并停止；已经认识的朋友也可再次选中。
3. 没命中好友时才判定明信片。
4. 命中明信片后从未拥有项随机选择。

音乐好友：

- 只读取活动开始时已经认识的好友集合。
- 空集合时不判定来访。
- 每位已认识朋友增加 15% 来访概率，统一封顶为 100%。
- 命中后从已认识好友等概率选择一位；课代饼、三好兔、心好兔、信号狗、饼哩饼哩分别固定赠送 4/6/8/6/4🍎。

### 15.2 播放器生命周期与游戏控件

- `BilibiliPlayerProvider` 持有受控业务状态与单份运行态；唯一 `PersistentPlayerDock` 通过 portal 固定挂在 `document.body`，不会因信息内容、收藏墙、维度或苹果钟焦点层切换而意外卸载。
- 选曲或详情挂载后立即请求 `autoplay=1`。展开态 iframe 可获得键盘焦点并接收鼠标/触摸交互；收起态容器设置 `inert`、`aria-hidden` 和 `pointer-events: none`，因此不可见、不可交互，但仍保留同一 iframe 节点。
- 显示/隐藏只改变画面尺寸，不重建 iframe 或重置游戏计时。暂停会冻结游戏估算进度并卸载 iframe 以停止声音；继续从估算秒数重建 iframe，取消则清除当前请求。
- 播放器展开时苹果钟信息卡自动收缩，隐藏画面时恢复展开。

### 15.3 曲目选择与状态

- V9 状态只保存当前 BV、索引和列表/单曲/随机模式。当前播放请求、暂停估算位置与画面展开状态只属于页面运行态，不进入存档。
- 唱片机面板标题为“八首全站第一”，按固定目录显示八首曲目，并提供列表、单曲、随机以及上一首、下一首游戏控件。
- 主动切歌与游戏计时结束策略分开：列表和单曲模式的上一首/下一首都移动到相邻项，随机模式主动选择其他项；只有游戏计时判断结束时，单曲模式才重播当前项，列表模式前进一首，随机模式另选一首。

### 15.4 静态 Pages 与计时边界

B 站 iframe 不向父页面提供可靠的播放状态接口。网页不能确认第三方内部的：

- 是否真的开始自动播放；
- 暂停、缓冲或拦截状态；
- 真实播放位置；
- 视频是否结束。

GitHub Pages 是静态托管，浏览器又不能伪造 B 站 Referer；API 与带签名的 DASH/MP4 流不能从当前 Pages Origin 稳定直取。构建时固化的流地址也会很快过期，因此不引入未知第三方代理，继续使用官方 iframe。当前策略为：

- `autoplay=1` 是请求，不是成功回执；有声自动播放仍可能被浏览器拦截，游戏不能强制或确认成功。
- iframe `load` 后按目录中的 `durationSeconds` 启动游戏计时；这个计时驱动尽力续播和循环，可能与第三方真实进度漂移。
- 暂停、继续和取消由父页面控制 iframe 生命周期，因此游戏侧状态可预测；继续位置仍是估算秒数，不能声称精确恢复。用户直接在跨域 iframe 内暂停或拖动时，父页无法读取该变化，游戏估算计时不会随之同步。
- 任务只记录“请求打开这个 BV”。

## 16. 现实生活维度

### 16.1 进入、离开与结算

- 只允许满足 `(hover: hover) and (pointer: fine)` 的 PC 主输入能力进入；不使用 UA 品牌名单或窗口宽度启发式。打开确认和最终提交前各检查一次。
- 非 PC 恢复停留在现实维度的存档时不篡改存档，只显示不可关闭的返回入口，显式 `reality/leave` 后照常结算。
- `reality/enter` 记录 `stayId`、绝对 `enteredAt`、`activeDurationMs: 0` 与当前 `leaseStartedAt`，并把 `world` 切为 `reality`。
- 页面持有租约时每 60 秒派发一次 `reality/session-heartbeat`，把自上个租约起点起的有效时长累计进 `activeDurationMs` 并重置租约起点。点 HUD“离开”、离开旅程或 `pagehide` 派发 `reality/session-suspend`；`pageshow` 或继续缓存只用当前时间重新开始租约，不补暂停/离线间隔。异常退出最多保留到最后一次已写入心跳。
- HUD 现实计时只显示累计完整分钟，点击它等同于返回游戏维度。
- `reality/leave` 按 `activeDurationMs + 当前仍有效的租约尾段` 计算 `floor(active / 10min)` 并返回游戏。结果不足 1🍎时不创建 `pendingSettlement`，直接结束；达到 1🍎时才要求回答“是的🥰”或“没有🥺”，前者获得全额，后者获得 `floor(full / 2)`。
- 结算有稳定 `stayId`；重复、过期或不匹配请求不会再次发奖。
- 现实停留和待决结算均写入存档。

### 16.2 二楼电脑：刷播与冲热

- 房间分别显示“刷播”和“冲热（开发中）”两个入口，不再使用“数据”总入口。冲热页只说明仍在开发，并由居中的“前往字母建设站”打开 `https://www.weibo.com/u/7878664767`，使用 `noopener noreferrer`。

- 输入框只接受一个可留空的裸 BVID 或 `http(s)` B 站完整视频链接；完整链接只从 `/video/<BV>/` 路径解析，成功后规范为 BVID。自测 BVID 与维度穿透开关写入 V9 的 `reality.streamSettings`；视频间隔、轮次间隔、登录模式、定时停止和运行进度仍是页面会话状态。
- 登录刷播只通过顶层 `window.open` 打开 `https://www.bilibili.com/video/<BV>/?autoplay=1&t=0`；父页面只持有窗口句柄以便关闭，不尝试跨域读取或控制页面内部状态。“弹出窗口”和“新标签页”都按顺序打开，任意一次被拦截时关闭本轮已打开页面并等待用户授权后重试。
- 实验性维度穿透游客刷播使用不可交互的官方播放器 iframe。开关开启且登录刷播未运行时自动启动；启动登录刷播会先停止游客刷播，登录任务结束后若开关仍开启则恢复游客刷播。两种方式互斥，GameHome 的调度器不随游戏/现实维度切换卸载。
- 两种方式每轮都重新随机排列去重后的静态目录，自测 BVID 从静态集合去重后始终追加在末尾；页面会话中的视频间隔与轮次间隔共用。默认视频间隔 8 秒，可在 1–60 秒内调节，设备或网络较卡顿时可适当增加；生产轮次间隔默认 310 秒，DEBUG 可在本次页面会话覆盖为 1–3600 秒。
- 游客刷播每轮从空 iframe 集合开始，按视频间隔逐个追加；最后一个 iframe 创建后，整轮集合保留到轮次截止，再统一卸载并创建下一轮，不在单个播放器初始化若干秒后提前销毁。隐藏层使用 `inert` 且不可交互；HUD 在两个维度都显示当前轮次与开始下一轮的倒计时。倒计时由控制器在 `performance.now()` 单调时钟域内计算剩余量，再交给 HUD 展示，不与 `Date.now()` 的墙钟混算。
- 最后一个页面实际打开后按当前轮快照的时长等待，生产默认 310 秒；到期关闭本轮全部页面并立即开始下一轮。另可设置本次任务在 0–24 小时后停止，0 或留空表示不限时；限时从开始任务时起算，运行中不会被表单变化改写。登录时提示尽量不要连续刷播超过 5 小时。
- 打开步骤、轮次结束和定时停止共用一个一次性计时器；后台冻结可能让动作延迟到恢复时，但恢复后只推进当前步骤，不连续补开错过的多轮。主动停止、定时完成、关闭游戏页或卸载组件都会清理计时器并关闭仍持有的窗口。
- 每轮完成只增加累计轮次；主动停止或到达限时后，才把整次启动任务按同一 `sessionId` 写成一条记录，其中包含起止时间、总完成轮次和 `completed | stopped` 结果。即使 0 轮也记录这次已启动任务，最近只保留 10 次。运行中的 BV 列表、模式、延迟、限时、轮次定时器和窗口句柄只属于当前页面会话。
- “游客刷播”只是产品模式名，不是匿名或未登录保证。游客 iframe 未使用 `credentialless`，也未通过 `sandbox` 剥离 B 站来源；浏览器会按自身第三方 Cookie 策略决定是否把当前浏览器已有的 B 站会话附到 iframe 内的 B 站请求。`allow="autoplay"` 只委托自动播放能力，`referrerPolicy` 只约束 Referer，不控制 Cookie。
- iframe 文档及其中的媒体、历史或心跳请求都由 B 站来源脚本发出。GitHub Pages 父页受同源策略限制，不能读取 B 站 Cookie、iframe DOM、播放器状态或响应，也没有实现 CORS 绕过；父页只控制 iframe URL、创建顺序、计时和移除。顶层窗口或 iframe 的创建、`load`、本地轮次完成和 HUD 倒计时都只说明本站发出了跨站加载请求，不能确认 B 站是否真实播放、播完或增加计数。

- 待办位于明信片选择器之前，可创建、编辑、标记完成/未完成和删除；数据写入 V9 存档。
- 苹果钟提供 25+5、50+10、90+15 三组“专注 + 休息”周期；状态保存 `focusEndsAt` 与 `cycleEndsAt` 两个绝对截止时间。
- 可选择已解锁明信片作为背景；启动后按 session 快照锁定收藏 ID，不复制图片或标题。
- 运行时使用全屏焦点 UI，把锁定的明信片以 `cover` 铺满背景并允许裁切，同时展示陪伴饼狗、待办、信息卡和可操作的游戏播放器控件；播放器展开时信息卡自动收缩，隐藏时恢复。
- 苹果钟可以取消；截止时间已到时必须完成，不能利用延迟 UI 取消绕过结果。
- 专注到点只切换到休息并提醒；休息到点完成整轮时才原子执行 `companionDays + 1`，并推进或结束活力七相伴日。重复 tick、未到点 tick 和截止前取消都不加天。
- 普通现实停留结算、待办 CRUD 与单独的待办到期通知不增加陪伴天数。
- 专注结束、整轮结束或已有到期时间的待办到期时，领域层签发稳定 notification effect，并记录已签发时间避免重复。

## 17. 通知、守候音频与 PWA

### 17.1 浏览器通知

- 只在用户点击“开启提醒”后调用 `Notification.requestPermission()`。
- 权限为 granted 时创建带稳定 `tag` 的系统通知；不支持、拒绝或构造失败时改用页内 toast。
- 页面计时器等待最近截止时间；`focus` 与 `visibilitychange` 后立即按绝对时间补检查。
- 页面完全关闭、浏览器冻结或设备休眠时不保证准点通知；本项目没有推送服务器或后台同步来绕过此限制。

### 17.2 守候音频

- 三个旅程入口的明确用户手势中创建或恢复一个 `AudioContext`。
- 单例 oscillator 为 10 Hz，gain 为 0.01；App 生命周期内复用。
- 运行期始终保持开启，不在状态栏暴露技术开关。
- App 卸载时停止 oscillator、断开节点并关闭 context。
- 这是保活的尽力措施，不能绕过浏览器后台冻结、系统节能或用户静音策略。

### 17.3 移动端屏幕常亮

- `useScreenWakeLock` 只在 `(hover: none) and (pointer: coarse)` 的移动主输入设备、旅程运行且页面可见时请求 Screen Wake Lock。
- 页面隐藏时释放，重新可见时再次请求；API 缺失或请求被拒绝时继续运行游戏。
- 屏幕常亮只减少前台熄屏，不能保证切到其他应用、锁屏或系统冻结后仍持续调度。

### 17.4 PWA 更新保护

- manifest 图标使用饼狗头像 PNG，包括 192、512 与 maskable 512；网页另有 favicon 32 和 Apple Touch 180。
- Service Worker 使用 prompt 更新模式。检测到新版本时自动下载当前缓存档，再提供安装并执行 reload。

## 18. DEBUG

- 可调未来活动时长与明信片、百万直拍、全站第一、旅行遇友、音乐好友五类概率。
- 快捷时长包括 10 秒、30 秒和历史 1 分 12 秒；新档默认选中 10 秒。
- 可把本次页面会话中的刷播轮次时长设为 1–3600 秒；正在播放的当前轮保持原时长，从下一轮或重新开始时采用新值。该设置不写入存档。
- DEBUG 不把意愿永久强制为 true；活力魔法仍是独立的游戏状态。
- “一键全收集”按当前三类收藏目录和好友目录即时写入记录。
- “清空收集”同时清空三类收藏与好友记录。
- 两个批量动作都二次确认并报告收藏与好友的实际变更数量。
- 不维护专用全收集 `.bingo`。

## 21. 安全、隐私与可访问性

- 不保存凭证、微博 Cookie、GitHub PAT 或 B 站登录状态。
- 外链使用 `noopener noreferrer`；不可信文本不传给 `innerHTML`。
- 存档按严格 schema 重建白名单字段，摘要校验在迁移之前。
- 对话框打开时移入并限制焦点，Escape 关闭，关闭后恢复到仍存在的触发点。
- 颜色不是意愿拒绝、任务完成或分类解锁的唯一信息。
- 电子琴键具有音名、物理键映射和按下状态；只映射白键。
- 隐藏滚动条仍保留键盘和触摸滚动。
- 动画遵循 `prefers-reduced-motion`。
- 自动播放、通知与更新不将请求误写为成功；守候音频不再占用用户状态栏。
