## 1. 已确定的产品边界

“旅行饼狗”是一款参考《旅行青蛙》节奏、以饼狗为主角的非官方粉丝向网页收集游戏。游戏本体必须在浏览器内独立运行：

- 不需要登录、不请求游戏后端、不上传玩家存档。
- 首次加载并缓存资源后，应能离线导入存档、计时、领奖和再次导出。
- 存档以 UTF-8 JSON 为内容、`.bingo` 为扩展名，由玩家每次进入时手动选择。
- 点击“离开铲铲饼屋”时先下载最新存档，再返回标题页。
- GitHub Pages 根首页只提供入口；游戏和 Service Worker 只占用 `/AllForSUXINHAO/TravellingBingo/`。
- `/AllForSUXINHAO/` 只保留并发布 `TravellingBingo/`；原有 `SUperView/`、`SUperDanmaku/` 已按用户要求删除。
- 页面明确标注“非官方、非商业粉丝作品”；人物事实、用户给定设定、粉丝二创设定和实现推断分层保存。

不在首版 Demo 范围内：账号系统、云存档、排行榜、真实支付、广告、用户跟踪、多人联机、运行时访问微博或 B 站接口。

## 3. 玩家流程

```text
根首页入口
  → 游戏标题页
  → 选择 .bingo 存档 / 开始新游戏
  → 校验与存档摘要确认
  → 铲铲饼屋
  → 旅行 / 刷播 / 冲热 / 房间互动 / 收藏册
  → 离开铲铲饼屋
  → 下载最新 .bingo
  → 返回标题页
```

首版 Demo 已把这条主流程接入真实领域状态与真实收藏目录：新游戏或导入存档后进入房间，购买补给，启动旅行 / 刷播 / 冲热，等待或用调试功能完成，领取预先确定的奖励，再查看收藏、导出并重新导入 `.bingo`。对应的 Playwright 场景位于 `tests/e2e/demo-journey.spec.ts`，桌面 Chromium 与 Pixel 7 均已通过。

### 3.1 标题页

首版 Demo 已提供：

- “选择 `.bingo` 存档”文件输入；
- “开始新游戏”；
- 游戏版本、非官方声明与 72 分钟玩法提示；
- 连续激活标题 5 次后的隐藏调试入口；
- 有未导出进度时的 `beforeunload` 提示。

选择存档后不会立即替换状态。页面先显示文件名、导出时间、苹果数、收藏进度、当前活动摘要以及 DEBUG 标记，玩家确认后才进入铲铲饼屋。PWA 已提供更新可用与离线就绪提示；固定文件名图片带内容 revision，素材更新不会继续复用旧缓存。

### 3.2 铲铲饼屋

房间以固定宽高比场景图为底层，DOM/SVG 百分比热区为交互层，饼狗透明角色层在最上方。所有热区同时支持鼠标、触屏和键盘，最小触控范围 44×44 CSS px。

| 位置 | 交互 | 首版 Demo 行为 |
|---|---|---|
| 床 / 沙发 | 休息 | 显示短休息反馈；不启动长任务 |
| 电脑 | 刷播 / 冲热 | 打开任务选择面板；同一时间只能有一个长任务 |
| 衣架 | 奇迹饼狗 | 显示下一阶段说明；换装小游戏尚未实现 |
| 电子琴 / 唱片机 | 休闲 | 显示静音休闲反馈；首版不播放音频 |
| 冰箱 | 道具商店 | 使用苹果购买出行、刷播、冲热所需补给 |

| 左上角门牌 | 离开 | 二次确认后生成并下载存档，再返回标题页 |

### 3.3 活动状态

长任务只有三种：

- `travel`：出去玩，核心产出明信片和苹果；
- `stream`：刷播，核心产出百万直拍海报；
- `trend`：冲热，核心产出更稀有的全站第一。

基础时长统一为 72 分钟，即 `4,320,000 ms`。任务开始后饼狗离开房间或进入电脑工作状态，期间不能启动第二个任务，但仍可查看收藏、设置和导出存档。

首版持久状态机保持精简：

```text
idle → running → ready → 领取（同一次 reducer 事务）→ idle
          │
          └──────────→ 调试立即完成 / 调试清除
```

`remainingSeconds` 不写入存档。存档只记录绝对的 `startedAt`、`endsAt`；页面每秒刷新显示，并在窗口重新获得焦点和 `visibilitychange` 时用当前时间重新推导状态。

### 3.4 首版 Demo 数值基线

所有数值放入内容配置，不硬编码在组件中，调试模式可以覆盖下一次任务的时长。

初始资源：18 个苹果、1 份普通旅行便当。基础补给：

| 道具 | 价格 | 用途 |
|---|---:|---|
| 普通旅行便当 | 3 🍎 | 启动旅行；无额外修正 |
| 苹果旅行便当 | 6 🍎 | 启动旅行；额外获得 2–4 苹果 |
| 信号耳机 | 4 🍎 | 启动刷播 |
| 热度工具箱 | 7 🍎 | 启动冲热 |
| 幸运苹果 | 10 🍎 | 作为任一任务附加道具，提高“新收藏”权重，不直接保证稀有掉落 |

奖励基线：

| 活动 | 固定奖励 | 收藏掉落 | 保底 |
|---|---|---|---|
| 旅行 | 4–8 🍎 | 1 张明信片；20% 触发好友事件 | 候选库仍有未收集项时优先新图 |
| 刷播 | 1–3 🍎 | 40% 获得百万直拍；重复海报折算 5 🍎 | 连续 2 次未掉落后，第 3 次必掉落 |
| 冲热 | 2–4 🍎 | 12.5% 获得全站第一；重复海报折算 12 🍎 | 连续 7 次未掉落后，第 8 次必掉落 |

“全站第一”必须明显比“百万直拍”稀有。掉落在任务开始时根据 `rewardSeed` 确定，并完整写入活动对象；重新打开、反复导入或修改显示时钟不能重抽。

新收藏选择采用加权池：未收集项权重 8，重复项权重 1；幸运苹果将未收集项权重提升为 16。已全收集时只抽重复奖励。

## 5. 收藏系统

统一收藏结构：

```ts
type CollectibleCategory = 'postcard' | 'million-shot' | 'site-first'

interface CollectibleDefinition {
  id: string
  category: CollectibleCategory
  title: string
  alt: string
  source: {
    platform: 'weibo' | 'bilibili' | 'bilibilitoy'
    url: string
    publishedAt?: string
    pageUrl?: string
    accessedAt: string
  }
  rights: 'user-confirmed-authorized'
  images: Array<{
    width: number
    height: number
    path: string
    byteLength: number
    mime: 'image/webp'
    sha256?: string
  }>
  tags: string[]
  metadata?: Record<string, string | number | boolean>
}
```

上面是三类收藏的共享投影；明信片另外包含 `caption`、`date`、原图摘要等专有字段。`public/data/` 中的三个目录分别使用严格的分类 Zod 契约；百万直拍编号、全站第一 BV 号、节目类别、fallback 类型和明信片源 ID 放在各自 `metadata`。启动时并行加载、校验和合并，失败则阻止进入游戏并给出可读错误。

存档只保存收藏 ID、首次获得时间和重复次数，不复制标题、URL 或图片路径。展示时从当前版本目录读取定义；新增收藏可直接进入新掉落池，若未来重命名既有 ID，则必须先设计存档迁移，当前 Demo 不自动猜测映射。

收藏册默认只加载缩略图；打开详情后加载合适尺寸的展示图。所有图片设置 `width`、`height`、`loading="lazy"`、`decoding="async"` 和准确中文 `alt`。小字排名信息必须同时用 HTML 文本展示，不能只藏在海报像素里。

### 6.2 导入规则

- 文件最大 1 MiB，先读文本再以 Zod 严格校验；未知顶层键默认拒绝。
- 只接受 `format === travelling-bingo-save`。
- 未来版本与旧于 v1 的版本均拒绝导入并给出可读提示；当前 Demo 尚未引入迁移链。
- 数值验证安全整数、非负范围和合理上限；收藏 ID 必须存在于当前目录。
- 校验完成前不修改当前游戏状态。
- SHA-256 用于检测损坏和手误，不是密钥签名，也不能防止玩家主动修改。
- 文件名、错误内容和存档文本绝不使用 `innerHTML`。

普通导出文件名为 `travelling-bingo-YYYYMMDD-HHmmss.bingo`，调试档在扩展名前附加 `-debug`；MIME 使用 `application/octet-stream`。规范 JSON 采用稳定键排序后计算摘要。

浏览器关闭事件不能可靠触发下载，所以不能承诺“直接关页面也自动保存”。有未导出变化时注册 `beforeunload` 提示；“离开铲铲饼屋”按钮才是可靠导出路径。

## 7. 定时与时间异常

首版领域函数的时间由 action 参数传入，因此单元测试可以精确控制边界；页面层每秒读取 `Date.now()` 刷新显示，并在窗口聚焦和 `visibilitychange` 时重算。任务是否完成只比较绝对的 `endsAt`，不依赖持续运行 72 分钟的 `setTimeout`，后台标签页休眠后也不会丢失任务。

当前 Demo 尚未持久化 `lastObservedAt`，也没有实现系统时钟大幅回拨后的冻结与恢复流程。若后续加入，应阻止负剩余时间和重复奖励，并允许玩家在恢复正确时间后继续或导出存档。

纯静态单机游戏无法真正防止修改系统时间，页面和文档不承诺反作弊。

## 8. 调试模式

标题在 3 秒内连续点击或键盘激活 5 次，弹出密码输入；严格匹配 `TravellingBingo` 后，仅在当前浏览器会话解锁：

- 设置下一次任务为 10 秒、30 秒或正常 72 分钟；
- 立即完成当前任务；
- 增加 20 个苹果；
- 一键全收集；
- 导出带 `DEBUG` 标识的调试存档。

领域层还支持调整道具、单项收藏和清除活动，首版 UI 暂未暴露这些高级按钮。密码存在公开前端代码中，只是隐藏入口，不是安全边界。普通存档不保存会话级解锁开关；一旦以调试模式开始或给当前档解锁，存档的 `profile.debug` 为 `true`，文件名包含 `debug`。

“一键全收集”直接按当前加载的收藏目录生成状态，因此会随 12 + 30 + 8 目录更新，不手工维护容易过期的 ID 列表。独立的调试 fixture 文件与 CI 覆盖检查可在后续需要时补充。

## 9. 技术栈与原因

| 层 | 选择 | 说明 |
|---|---|---|
| 运行环境 | Node.js 24 LTS + npm | 本机与 CI 统一；Node 24 当前为 LTS |
| 构建 | Vite 8 | 纯静态构建、子路径 `base`、开发体验简单 |
| UI | React 19 + TypeScript 5.9 | 组件化场景、严格类型；暂不采用 TypeScript 7，避免 ESLint 生态范围冲突 |
| 状态 | React 本地状态 + 显式 domain reducer | 首版不需要全局 store；持久状态可序列化、可测试，Zustand 仅保留为扩展依赖 |
| 校验 | Zod | 存档与内容清单运行时校验 |
| 动画 | CSS | 首版房间、角色和卡片动效不需要游戏引擎；Motion 已安装但未作为首版运行依赖使用 |
| 离线 | vite-plugin-pwa + Workbox | App Shell 预缓存、收藏图片按需缓存 |
| 图片 | Sharp + FFmpeg/ffprobe | WebP 多尺寸、HEIC tile-grid 正确拼合 |
| 测试 | Vitest + Testing Library + Playwright | 领域、组件、真实下载/上传流程分层验证 |
| 规范 | ESLint 10 + Prettier | UTF-8、自动格式和 CI 门禁 |

不采用 React Router：首版 Demo 用单页面状态机切换标题、房间和面板，避免 GitHub Pages SPA 回退问题。不采用大型游戏引擎：核心是 DOM 场景、菜单、计时和收藏，不需要实时碰撞或帧循环。

### 10.1 持久状态与 UI 状态分离

持久状态只包含会影响游戏结果的字段；当前打开哪个面板、动画进度、筛选关键词、弹窗是否展开都属于 UI 状态，不写入存档。

```ts
interface ActivityRun {
  runId: string
  kind: 'travel' | 'stream' | 'trend'
  startedAt: number
  endsAt: number
  rewardSeed: string
  rewardPlan: RewardPlan
  supplyId: ItemId
  usedLuckyApple: boolean
}
```

领奖事件必须携带 `runId`。Reducer 只有在它与当前活动一致且状态为 `ready` 时才发奖，然后在同一个不可分割的状态变更中写入奖励、统计、保底计数并清空活动，避免双击重复领奖。

## 11. PWA 与性能

Service Worker 的 `scope`、manifest `id`、`start_url` 和 Vite `base` 全部固定为：

```text
/AllForSUXINHAO/TravellingBingo/
```

缓存策略：

- App Shell、JS、CSS、HTML、JSON、manifest 和 SVG 图标由 Workbox 预缓存；
- 收藏图片使用独立 `CacheFirst` 缓存，访问后可离线读取；
- 铲铲饼屋和饼狗 v2 使用独立 `CacheFirst` 缓存；
- 首版没有“下载全部离线素材”按钮，未访问过的高清收藏不能承诺离线可用；
- PWA 缓存不作为权威存档，不保存玩家唯一进度。

预算：

| 项目 | 目标 |
|---|---:|
| App Shell 初始传输 | ≤ 2 MiB |
| 初始预缓存 | ≤ 5 MiB |
| JS gzip | ≤ 150 KiB |
| CSS gzip | ≤ 50 KiB |
| 缩略图 | 通常 ≤ 60 KiB |
| 单张展示图 | 通常 ≤ 500 KiB |
| 首版全部部署产物 | ≤ 150 MiB |

生产构建关闭 sourcemap，避免把 `sourcesContent` 随 Pages 产物公开。上表仍是定版预算；加入真实房屋、角色和 50 项收藏后的最终构建体积，必须以本轮 `build / site:assemble / site:verify` 输出重新核对，不能沿用早期空壳数据。

## 13. 安全、隐私与可访问性

- 首版运行时不依赖第三方字体或素材 CDN；正式发布前继续核对构建产物不存在外域运行时请求。严格 CSP 仍是上线加固项，当前不能写成已启用。

- 不加入统计、追踪、指纹或用户数据收集。
- 导入数据经 schema 重建白名单对象，防止原型污染和任意 HTML 注入。
- 主要操作已使用按钮、对话框、区域、标签页等语义结构，并提供可见焦点样式；最终键盘流程仍需浏览器验证。
- 支持 `prefers-reduced-motion`；颜色不作为唯一状态信息。
- 首版不自动播放音频，当前休闲区域只显示静音反馈；静音和音量设置尚未实现。
