# 旅行饼狗网页完整实现方案

> 原始需求：[旅行饼狗开发纲要](specs/旅行饼狗开发纲要.md)
>
> 固定路径：`https://emmm1e3m.github.io/AllForSUXINHAO/TravellingBingo/`

## 1. 产品定义

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。玩家在铲铲饼屋陪饼狗旅行、刷播、冲热、弹琴和睡觉，通过读条、Bingo 小任务、收藏与好友积累陪伴回忆；也可以切换到现实生活维度，用苹果钟和待办让游戏陪伴真实工作与学习。

产品原则：

- 房间是视觉主体，信息栏只解释当前语境与可执行动作。
- 饼狗有自己的旅行、电脑和音乐意愿；拒绝是可见状态，不是隐藏入口。
- 五类饼屋读条共享二次确认、绝对时间、取消、领取和存档恢复规则；现实苹果钟使用独立的绝对时间完成流程。
- 🍎 的获得与花费都有明确来源；金额一律显示为 `N🍎`。
- 收藏与好友以第一次相遇为惊喜，不提前展示灰色占位、未解锁分类或永久总数。
- 游戏状态与第三方播放器、浏览器通知等外部能力严格分层；不可观测的外部状态不得被伪装成成功。
- `.bingo` 由玩家自己保管，不上传、不登录。

## 2. 运行与公开边界

- 游戏固定部署在 `/AllForSUXINHAO/TravellingBingo/`；根首页只提供入口。
- Vite `base`、PWA `id`、`start_url`、`scope` 与导航回退均使用该子路径。
- 游戏不需要后端、数据库、排行榜、支付、广告、统计或用户跟踪。
- 首次在线访问并缓存应用外壳后，标题页、房间、计时、领奖和存档可离线使用；第三方 B 站 iframe 与未缓存高清图不承诺离线可用。
- 运行时不调用 B 站收藏夹 API，也不跨域抓取微博图片。收藏、好友和唱片机目录在构建期固化为同源 JSON；刷播只读取随版本发布的两份同源 TXT。
- Pages 只上传隔离组装的 `_site/`，不公开 `docs/`、`research/`、`resources/raw/`、源码、浏览器状态或抓取凭证。

## 3. 主流程

```text
根首页入口
  → 标题页
      ├→ 检查更新
      ├→ 有缓存时“继续”
      ├→ “全新旅程” → 输入系统称呼并开始
      └→ “本地存档” → 选择 .bingo → 摘要预览 → 确认导入
  → 铲铲饼屋
      ├→ 房间空白 → 当前任务与意愿概览
      ├→ 设施 → 对应信息栏
      ├→ 读条活动 → 二次确认 → running / ready
      │    ├→ ↩️ 取消：不计天、不退款、不发奖
      │    ├→ 速度魔法：立即 ready
      │    └→ 领取：陪伴天数 +1
      ├→ 收藏墙 → 收藏 / 好朋友 / 视频详情
      ├→ 唱片机 → 持久播放器
      ├→ 电子琴 → 四排琴键
      ├→ ℹ️ → 简洁的“铲铲饼屋的小纸条”
      └→ 右下维度按钮
           ├→ 游戏维度
           └→ 现实维度 → 刷播 / 冲热（开发中） / 工作
                ├→ 刷播：打开独立竖屏页并以静默/标签页/窗口方式循环调度；可信 started 后当日首次得 20🍎
                ├→ 苹果钟完成专注与休息整轮：陪伴天数 +1
                └→ 返回结算：只结算 🍎，不加天
  → 离开房间 → 浏览器缓存保留当前进度 → 返回标题页
```

## 4. 标题页、更新检查与称呼

- 标题页在存在缓存时显示“继续”，并始终提供“全新旅程”“本地存档”和“检查更新”。首次进入或从旅程返回标题页时自动检查一次，同一次停留不因重绘重复触发，按钮仍可手动再查。
- 两个圆形头像下方、缓存/导入记录上方显示更新公告卡；房间左上角 `#️⃣` 打开同一份公告。公告内容由单一数据源维护，两处都显示 `v0.10.1`，明确说明“刷播现在可以正常使用了”，并列出奇迹饼狗、多套造型与合拍相册。标题页卡片右侧 meta 纵向排列，独立版本胶囊在原日期上方；左侧标题不再混入版本，日期位置与样式保持不变。房间弹窗继续显示自己的版本胶囊。
- 称呼去除首尾空白，接受 1–16 个非空 Unicode 字符；不合格时在输入框附近说明。
- 导入预览显示文件名、导出时间、游戏版本、称呼、陪伴天数、`N🍎`、收藏数量和当前活动。
- 文件选择只创建待确认预览，不立即覆盖内存状态。
- 自动与手动“检查更新”共用当前 Service Worker registration 的 `update()`、检查状态和结果提示；没有 Service Worker、尚未注册或网络失败时显示相应状态。
- 检查结果使用临时提示，不作为固定页面元素；检测到新 Service Worker 时自动下载当前缓存档，再提供安装更新。
- 连续激活标题五次后可输入 `TravellingBingo` 解锁 DEBUG；它是隐藏入口，不是安全边界。

## 5. 视觉、字体与通用文案

### 5.1 字体

| 用途                               | 字体       | 公开文件                              |
| ---------------------------------- | ---------- | ------------------------------------- |
| 展示标题、强调、房间设施与 HUD     | 可画乐融融 | `assets/fonts/kehua-lerongrong.woff2` |
| 正文、说明、表单、按钮、任务与日期 | 可画奶糖体 | `assets/fonts/kehua-naitang.woff2`    |

字体源位于 `resources/raw/travelling-bingo/fonts/`，公开页面保持上述路径和 CSS 字体族不变，发布“《现代汉语常用字表》2500 个常用字 + ASCII/中文标点 + 当前运行时表外用字”的 WOFF2。固定常用字表位于 `scripts/assets/data/modern-chinese-common-2500.txt`，构建和校验不依赖联网；新增普通常用字文案无需重建，新增表外字会由素材校验提示重建。界面只使用真实存在的可画乐融融与可画奶糖体：展示层负责标题、强调与 HUD，正文层约 `0.9rem`，辅助说明层约 `0.82rem`；正文、说明和表单都使用更易读的可画奶糖体。金额中的苹果数字仍使用乐融融，日期中的“月”等汉字使用奶糖体。

### 5.2 货币与固定文案

- 可见金额统一为 `N🍎`，例如 `3🍎`、`还差 2🍎`、`朋友送来 3🍎`。
- 不显示“X 个苹果”“补充·X个苹果”“按钮仍然可以按”等元叙述。
- “苹果”文字只用于角色口味、道具名称和“今天也要好好吃苹果”等自然语句。
- 冰箱标题为“补充道具”，不重复“为冰箱”。
- 衣架正文为“什么样的搭配最合适呢？”。
- 刷播说明为“在电脑前好好陪伴，加速百万直拍的达成。”
- 空收藏墙文案为“惊喜会在相遇时悄悄出现。”

### 5.3 控件

- 触控目标至少 `44 × 44 CSS px`，具备焦点圈、按压反馈和可理解的可访问名称。
- 房间设施用文字标签，不要求玩家猜抽象图标。
- 顶栏按性质分为左侧导航组与右侧运行/资源组，在可用宽度内自适应收缩且不互相遮挡；各 HUD 文字使用同一字号等级。
- 现实分钟、活力、🍎、收藏墙和 DEBUG 均为可点击入口。现实分钟等同于返回游戏维度，活力等同于点击饼狗；旧“状态正常”不再显示。刷播启动后，HUD 只显示启动中、运行中或停止中并可打开工具；轮次、倒计时、完整运行详情和记录只在独立在线刷播工具中展示。
- 信息栏顶行只保留语境标签；点击房间空白即可回到任务与意愿概览。
- 设施信息使用常规左对齐的读条卡层级，不复用大型居中结果页布局。
- `ℹ️` 按当前维度打开简洁说明；游戏维度不扩写成长篇设施或价格手册，现实维度需要说明苹果钟与 🍎 结算。

### 6.1 唯一母版

母版为用户提供的 1098 × 1433 RGBA 原图。应用目录 `AllForSUXINHAO/TravellingBingo/` 下的公开派生图沿用兼容文件名：

处理只允许等比缩放和无损 WebP 编码；不得裁切、重绘、补画、改变构图或丢失透明通道。

### 6.2 桌面与移动布局

- 顶栏、房间和信息栏共享页面 inset。房间左侧与顶栏左侧对齐，信息栏右侧与顶栏右侧对齐。
- 房间到信息栏的横向 gap 与顶栏到内容的纵向 gap 使用同一紧凑 token。
- 纵向透明房图在横向房间卡内以 `contain` 居中完整显示，不拉伸、不裁切；母版以外的左右空间保持透明留白，不叠加内侧竖向底板。交互坐标相对实际图片舞台定位。
- 房屋与信息栏不做展开/收起动画；切换不同信息内容时使用轻量 keyed 入场动画。
- 宽度不超过 960px 时页面按房间在上、信息区在下的顺序变为单列全宽；桌面保持房间在左、信息区在右。关闭、取消、维度切换和播放器控制必须留在视口或可滚动范围内。
- 隐藏滚动条不等于禁止滚动；滚轮、触摸、方向键和 PageUp/PageDown 仍要工作。

### 7.1 目录不是存档

存档不保存：

- 收藏分类总数、总收藏数或完成百分比；
- 全站第一的“下一项”索引；
- 分类解锁数组；
- 好友总数与图片元数据；
- B 站标题、作者、海报或视频目录副本。

完成度、可见分类、下一项全站第一和播放器展示信息均由“当前目录 + 存档 ID”派生。目录增加项目时旧档无需重置。

## 8. `.bingo` 导入、导出与迁移

### 8.1 外层格式

- UTF-8 JSON，扩展名 `.bingo`，MIME `application/octet-stream`。
- 外层包含格式标识、封套版本、`gameVersion`、导出时间、业务 payload 与 SHA-256 摘要。
- 最大 2 MiB；未知字段由严格 Zod schema 拒绝。极限回归覆盖 200 条最长中文待办与最大衣柜/相册结构，并要求导出实测跨过旧容量阈值、仍小于 2 MiB。
- SHA-256 只用于发现损坏或误改，不是签名或加密。

### 8.2 V12 缓存与导出

- 日常成功动作同步写入版本化 `localStorage` 单槽缓存；缓存不可用时才注册离开提醒。
- 通过“全新旅程”或“本地存档”覆盖缓存前先下载旧缓存；首次获得新的全站第一或认识新朋友构成关键节点，每到关键节点、每隔三天、检测到网页更新时自动请求 `.bingo` 备份。
- 周期备份以 `lastPeriodicBackupRequestedAt ?? firstCachedAt` 为基准判断三天间隔；成功请求后更新周期备份时间，避免重复下载。
- 产品界面显示 `v0.10.1`；新导出只写 `schemaVersion: 12`，`gameVersion: 0.10.1`。
- 用户名、天数、活动、任务、随机序列、收藏、好友、七种道具、魔法、现实、待办、苹果钟背景引用、播放器设置、自测 BVID、所选收藏夹、每日刷播奖励日期，以及奇迹饼狗的商店、已购素材、多套双轴形象、合拍构图与独立照片装饰完整往返；旧版刷播兼容历史字段只读保留，主游戏不再写入新的轮次或会话统计。当前播放请求、暂停位置、画面展开状态、独立刷播窗口、iframe、限时、保活音频、独立页 DEBUG 和完整合成图不写入存档。
- 浏览器缓存 payload 迁移到 V12、平衡规范化、目录协调或暂停旧页面租约产生新对象时，同步写回 V12 payload、当前 `gameVersion` 与新的 `updatedAt`；`saveId`、`firstCachedAt`、周期备份时间及外层 `cacheVersion: 1` 保留。
- 正常文件名为 `travelling-bingo-YYYYMMDD-HHmmss.bingo`；DEBUG 在扩展名前加 `-debug`。
- 离开房间只返回标题页，不清除浏览器缓存；`.bingo` 继续作为显式备份与跨浏览器导入格式。

### 8.3 V1–V12 导入顺序

1. 先按文件原始 payload 校验摘要。
2. 用严格 V1–V12 schema 解析；V1–V11 历史 schema 保持冻结。
3. 逐代迁移到 V12；历史 V6→V7 仍将每条旧轮次如实迁为一条独立 legacy 会话，V7→V8 初始化冻结刷播设置，V8→V9 为现实停留增加累计有效时长和可暂停租约，V9→V10 保留自测 BVID 并选择默认收藏夹；V10→V11 根据持久种子和当前游戏日初始化衣柜，把尚未领取的旧睡觉 `rewardPlan.baseApples` 归零，原刷播历史只作冻结兼容数据保留；V11→V12 再升级双轴构图、照片装饰、苹果钟背景引用与每日刷播奖励状态。
4. 规范非 DEBUG 状态未来活动的默认平衡。
5. 用当前目录协调可安全修复的旧引用。
6. 最终语义校验通过后才允许确认进入。

迁移不变量：

- 旧活动的 `startedAt`、`endsAt`、`rewardSeed` 原样保留；`rewardPlan` 通常也保留，唯一例外是 V10→V11 会把尚未领取的旧睡觉 `baseApples` 强制改为 `0`。
- 当前默认 10 秒只影响迁移之后新开始的活动。
- 历史用户名缺失时使用兼容称呼；陪伴天数由旧领取统计推导。
- V3 活动、好友与意愿字段保留；V4/V5 新字段使用安全初值，V1–V5 迁移到冻结 V6 时初始化空刷播历史，再迁到 V7 会话历史、V8 冻结刷播设置、V9 现实计时租约、V10 所选收藏夹设置、V11 衣柜状态，最后迁到 V12 双轴构图与每日刷播奖励状态。
- V10 已冻结；V10→V11 增加一件初始赠送服装、由原随机种子与 `companionDays` 从日初未拥有池生成的最多三件商品、空形象与空合拍相册，并把尚未领取的旧睡觉奖励归零；除此之外不重算旧活动、收藏、好友、任务或现实租约。
- V11 同样冻结；V11→V12 把所有旧 `scale` 复制为相等的 `scaleX/scaleY`，为旧合拍补 `decorations: []`，把旧苹果钟的明信片 ID 映射为 `{ kind: 'postcard', id }` 背景引用，并初始化 `streamDailyReward.lastRewardDateKey: null`。迁移不补发每日刷播奖励，也不重算冻结的旧刷播历史。
- 旧 V8 活跃现实停留没有心跳证据，V8→V9 时保留停留身份与原进入时间，但令 `activeDurationMs = 0`、`leaseStartedAt = null`；不使用缓存更新时间猜测在线时长或补发离线奖励。
- 当前版本不允许退役的 `greet-bingo` 留在任务板；迁移按当前任务目录替换，并保持任务 PRNG 可重现。
- 任务板以 `completedAt` 记录最后一项完成时间；全完成板保留到下一次游戏日（陪伴日）推进再刷新。任一任务未完成时，跨游戏日原样继承任务与完成状态。

## 12. 概率、好友与收藏顺序

```ts
DEFAULT_GAME_BALANCE = {
  activityDurationMs: 10_000,
  probabilities: {
    postcard: 0.65,
    millionShot: 0.3,
    siteFirst: 0.15,
    travelFriend: 0.1,
    musicFriend: 0.15,
  },
}
```

- 所有判定使用 `roll < chance`；0 永不命中，1 必定命中。
- 概率加成统一基于未增强基础值：`min(1, base + base × max(同类加成比例))`。同类加成只取最高比例，不在增强结果上继续复合。
- 苹果旅行便当只把当次旅行的 `travelFriend` 基础概率翻倍，默认 0.1 → 0.2；幸运苹果只把当次活动对应的收藏基础概率翻倍，不改变遇友概率。UI 只使用符合情境的“翻倍”，不展示“增加 100%”的实现表达。
- 已集齐分类，或基础概率为 0 / 1 时，不能浪费幸运苹果。

旅行顺序：

1. 判定 `travelFriend`。
2. 命中后从完整五人候选池选择好友，签发对应固定道具与按身份 2/3/4/3/2🍎 礼物并停止；已经认识的朋友也可再次选中。
3. 没命中好友时才判定明信片。
4. 命中明信片后从未拥有项随机选择。

音乐好友：

- 只读取活动开始时已经认识的好友集合。
- 空集合时不判定来访。
- 每位已认识朋友增加 15% 来访概率，统一封顶为 100%。
- 命中后从已认识好友等概率选择一位；课代饼、三好兔、心好兔、信号狗、饼哩饼哩分别固定赠送 4/6/8/6/4🍎。

### 15.2 播放器生命周期与游戏控件

- `BilibiliPlayerProvider` 持有受控业务状态与单份运行态；唯一 `PersistentPlayerDock` 通过 portal 固定挂在 `document.body`，不会因信息内容、收藏墙、维度或苹果钟焦点层切换而意外卸载。
- 选曲或详情挂载后立即请求 `autoplay=1`。展开态 iframe 可获得键盘焦点并接收鼠标/触摸交互；收起态容器设置 `inert`、`aria-hidden` 和 `pointer-events: none`，因此不可见、不可交互，但仍保留同一 iframe 节点。

- 播放器展开时苹果钟信息卡自动收缩，隐藏画面时恢复展开。

### 15.3 曲目选择与状态

- 当前 `musicPlayer` 只保存 BV、索引和列表/单曲/随机模式。当前播放请求、暂停估算位置与画面展开状态只属于页面运行态，不进入存档。
- 唱片机面板标题为“八首全站第一”，按固定目录显示八首曲目，并提供列表、单曲、随机以及上一首、下一首游戏控件。
- 主动切歌与游戏计时结束策略分开：列表和单曲模式的上一首/下一首都移动到相邻项，随机模式主动选择其他项；只有游戏计时判断结束时，单曲模式才重播当前项，列表模式前进一首，随机模式另选一首。

### 15.4 静态 Pages 与计时边界

B 站 iframe 不向父页面提供可靠的播放状态接口。网页不能确认第三方内部的：

- 是否真的开始自动播放；
- 暂停、缓冲或拦截状态；
- 真实播放位置；
- 视频是否结束。

GitHub Pages 是静态托管，浏览器又不能伪造 B 站 Referer；API 与带签名的 DASH/MP4 流不能从当前 Pages Origin 稳定直取。构建时固化的流地址也会很快过期，因此不引入未知第三方代理，继续使用官方 iframe。当前策略为：

- `autoplay=1` 是请求，不是成功回执；有声自动播放仍可能被浏览器拦截，游戏不能强制或确认成功。
- iframe `load` 后按目录中的 `durationSeconds` 启动游戏计时；这个计时驱动尽力续播和循环，可能与第三方真实进度漂移。
- 暂停、继续和取消由父页面控制 iframe 生命周期，因此游戏侧状态可预测；继续位置仍是估算秒数，不能声称精确恢复。用户直接在跨域 iframe 内暂停或拖动时，父页无法读取该变化，游戏估算计时不会随之同步。
- 任务只记录“请求打开这个 BV”。

### 16.3 搭配与持久变换

- 搭配目标为 `bingo | FriendId`；只展示当前已经认识的朋友。画布把对应透明海星体与全部衣服元素放在同一个组合坐标系内，该组合层宽度固定为父画布的 50%；元素的归一化位置和双轴尺寸都相对此组合层解释，角色缩小后配饰不会错位。
- 编辑草稿留在组件内；支持点击/拖动，左上手柄分别调整横向和纵向拉伸，右下手柄等比缩放并旋转。右栏把画布图层放在素材选择器之上，已拥有素材按套装、头饰、面饰、配饰和道具的非空分类筛选；🔼、🔽、🔄️、❌ 四个按钮在同一行，分别执行向前一层、向后一层、恢复默认变换和移除，并通过 `aria-label` 与 `title` 提供完整名称。照片图层不再附加人物/元素类型括注，同名项用顺序号区分；页面移除重复的选择数量、拖动手柄与已拥有素材说明。同一素材可重复放置。同一角色可创建、命名、切换、更新和删除最多 8 套造型；名称 1–20 字符，每套使用稳定 `lookId`。保存形象时每个元素只写 `placementId`、`assetId`、归一化中心 `x/y`、相对 `scaleX/scaleY`、规范化 `rotation` 和唯一局部 `z`，两轴都以组合层宽度为基准，`scaleX === scaleY` 时保持天然长宽比，每套形象最多 12 个元素。
- 搭配室可把当前角色、海星体与尚未保存的编辑草稿直接渲染成透明背景 PNG 下载；这个下载不把位图写进存档。
- 存档不得包含素材 URL、`data:image`、`blob:`、Canvas 输出或完整合成图。目录名称、图片路径和基准尺寸由当前版本静态素材表提供。

### 16.4 合拍、相册与 PNG

- 合拍复用苹果钟的 `PostcardPicker` 选择弹窗，但只传入已拥有明信片并关闭白纸选项，也不提供已保存合拍，因此白纸或历史合拍不能成为持久背景。另提供临时本地图片背景，支持 PNG、JPEG、WebP 与 AVIF，并按天然宽高调整 DOM 预览与 Canvas 画布；即使没有收藏明信片也保留本地上传与构图入口。当前背景完整铺满且不加灰色遮罩。参与角色数组必须包含 1–6 位可用角色，已认识朋友可以单独组成照片；人物按各自归一化 `x/y/scaleX/scaleY/rotation/z` 绘制，并支持主体拖动与角落手柄双轴变换。“清空画布”只清除参与者、独立装饰与当前选中项，不改变当前明信片或本地图片背景。
- 明信片模式保存合拍时冻结各人物当时的轻量搭配快照，之后修改当前形象不改变旧照片。每张最多 6 人，相册最多 40 张；照片只保存 `postcardId`、人物稳定 ID、双轴构图变换、衣服图层快照和创建时间。本地模式改为“下载当前合拍”，隐藏相册保存按钮；`savePhoto()` 还必须硬拒绝，临时草稿使用 `postcardId: null`，不得 dispatch `wardrobe/photo-create` 或写入 `GameState`。
- 每张照片还可添加最多 12 个独立 `decorations`。它们属于整张照片而非任何人物，持久化 `placementId`、`assetId` 与 `x/y/scaleX/scaleY/rotation/z`；人物和装饰共享照片级全局唯一 `z` 并可互相穿插，人物内部服饰继续使用该人物自己的局部 `z`。合拍右栏同样先显示照片图层，再显示按分类过滤的独立元素选择器，并复用搭配室的一行四图标操作。
- 本地预览 object URL 只属于组件内临时状态：上传失败立即释放，成功替换时释放旧值，显式改回明信片或组件卸载时释放。导出另建输入 object URL，通过 `backgroundOverride` 交给现有 Canvas 下载链，并在 `finally` 释放；输出 PNG URL 继续由下载器短期释放。本地文件、URL 与像素结果都不能进入相册或存档。
- 收藏墙提供独立“合拍相册【N】”，不计入收藏进度。列表中的整张卡片与预览统一为 4:3，使用 `PhotoCompositionPreview mode="cover"` 居中裁切铺满；打开详情后改用 `mode="natural"`，按对应明信片原始宽高计算媒体区，并以 `contain` 完整显示在视口中。支持删除指定照片；导出使用同源 Canvas、优先 960 明信片并回落 480 图，默认长边 2400、短边按明信片比例计算，下载接管后再释放临时 object URL。

### 16.5 ImageGen 素材

- `饼狗海星体参考.jpg`、`衣服.jpg` 和 `配饰.jpg` 只作为造型、套装与元素参考。ImageGen 重绘六个透明海星体、每套完整服装和全部配饰，不能带入原图水印、文字、白底、人物残肢或不相关元素。

## 17. 现实生活维度

### 17.1 进入、离开与结算

- 电脑端和移动端均可进入现实维度并恢复其中的存档，不在维度入口做设备限制。
- `reality/enter` 记录 `stayId`、绝对 `enteredAt`、`activeDurationMs: 0` 与当前 `leaseStartedAt`，并把 `world` 切为 `reality`。
- 页面持有租约时每 60 秒派发一次 `reality/session-heartbeat`，把自上个租约起点起的有效时长累计进 `activeDurationMs` 并重置租约起点。点 HUD“离开”、离开旅程或 `pagehide` 派发 `reality/session-suspend`；`pageshow` 或继续缓存只用当前时间重新开始租约，不补暂停/离线间隔。异常退出最多保留到最后一次已写入心跳。
- HUD 现实计时只显示累计完整分钟，点击它等同于返回游戏维度。
- `reality/leave` 按 `activeDurationMs + 当前仍有效的租约尾段` 计算 `floor(active / 10min)` 并返回游戏。结果不足 1🍎时不创建 `pendingSettlement`，直接结束；达到 1🍎时才要求回答“是的🥰”或“没有🥺”，前者获得全额，后者获得 `floor(full / 2)`。
- 结算有稳定 `stayId`；重复、过期或不匹配请求不会再次发奖。
- 现实停留和待决结算均写入存档。

### 17.2 二楼电脑：刷播与冲热

- 房间分别显示“刷播”和“冲热（开发中）”两个入口，不再使用“数据”总入口。原有设备能力判断仅拦截冲热，并用自然的电脑端提示引导用户先使用刷播或工作计时。冲热页只说明仍在开发，并由居中的“前往字母建设站”打开 `https://www.weibo.com/u/7878664767`，使用 `noopener noreferrer`。
- 主游戏只保存收藏夹与可留空的自测 BVID，并在本次打开工具时选择定时停止与初始播放方式；自测视频规范为 BVID，与所选收藏夹一起写入当前 `reality.streamSettings`。播放方式属于独立工具页运行配置，不扩展严格 V12 游戏存档。
- `useStreamPlayback` 必须在开始按钮的同步用户手势中只打开一个名为 `SUperView` 的 430 × 760 窗口，地址为同源 `stream-player.html`，参数包括 `favoriteId`、`selfTest`、`stopHours`、`mode`、`sessionId` 和 `autostart=1`。弹窗被拦截时不启动任务，只提示允许本站弹出窗口后重新开始。主游戏只传初始配置和接收可信生命周期消息，不接管独立页调度。
- 独立页产品名为“在线刷播工具”，可以从 URL 自动带入设置并开始，也可以在自身 UI 修改收藏夹、自测视频、定时停止与播放方式后手动开始；无参数直接访问仍完全可用。播放方式互斥为 `silent`（静默播放）、`tab`（新标签页）与 `popup`（弹出窗口），旧 URL 缺少 `mode` 时默认 `silent`，非法显式值必须给出页面内错误。主游戏与独立页都必须提示“请在网页版哔哩哔哩设置‘自动开播’和‘播完暂停’。”以及“静默播放功能在某些条件下可能失效，因此请务必检查轮次和自测视频涨幅的关系。”；账号、返回游戏与移动端提醒保持，删除新设备检查提示。
- 刷播清单的唯一运行源是 `favourites/3682220021.txt`（刷播收藏夹）与 `favourites/3986840044.txt`（测试收藏夹），UTF-8、每行一个 BV。构建把两份文件复制到发布页同源目录；只有显式 `npm run research:sync:favourites` 联网更新，运行时不请求 B 站收藏夹 API、不读取第三方目录页面，也不使用 CORS/HTML 代理。旧视频目录中的 streaming 字段不再参与刷播。
- 每轮从所选 TXT 使用 Fisher–Yates 重新随机，自测 BVID 固定追加在末尾。首个播放目标立即创建，之后固定每 5 秒创建一个。静默播放创建带 `autoplay=1`、`muted=1`、`danmaku=0`、`t=0` 的官方播放器 iframe；新标签页与弹出窗口共用 `https://www.bilibili.com/video/<BVID>/?autoplay=1&t=0`，只由 `window.open` 特征区分。打开回调必须明确返回成功；首个目标成功后才发 `started`，被浏览器拦截时不增加打开数、不续调度且不发每日奖励。界面不描述内部去重行为。
- 最后一个播放目标创建后才以 `Date.now()` 设置轮次截止，生产默认等待 310 秒。到期先统一移除本轮全部 iframe，再完成轮次并立即开始下一轮；不得在单个目标初始化 10 秒后销毁。新标签页与弹出窗口以 `opener = null` 和本站隔离，由用户自行关闭，主游戏停止刷播不负责关闭这些完整视频页面。0–24 小时的定时停止同样使用绝对截止，0 或留空表示不限时。
- `StreamRoundScheduler` 只维护下一个绝对截止和一次性 timer。`visibilitychange` / `pageshow` 恢复后调用 `reconcile()` 处理当前到期动作，不用每秒递增计时器，也不连续补开错过的多轮。主动停止或限时完成清理 timer 与当前模式的全部目标；页面卸载再释放保活音频。
- 在线刷播工具页面挂载即播放循环的低音量 WAV 作为尽力保活，空闲、运行与停止后都保持，只有页面卸载时释放。静默模式 iframe 始终真实存在；DEBUG 关闭或未选择显示时，host 与 iframe 都固定为视口内 `1 × 1px`，透明度 `0.01`、`pointer-events: none`，不得使用视口外定位、`display:none` 或 `visibility:hidden`。同时保持 `aria-hidden`、`inert`、`tabIndex=-1`，DEBUG 显示后才恢复 16:9 画面。
- 独立页大标题连续点击 5 次后出现密码框，密码严格为 `SUperView`。解锁状态写入独立页 `localStorage`，重开页面自动恢复；“关闭 DEBUG”清除状态，再次开启需要重新验证密码。DEBUG 可修改本页轮次间隔并切换播放器显示；主游戏 DEBUG 不再提供刷播轮次设置，两者完全解耦。
- 主游戏 HUD 只从独立窗口生命周期显示刷播启动中、运行中或停止中，点击可聚焦仍存在的在线刷播工具，并在窗口已关闭时回到刷播面板；它不接收或展示轮次、下一轮倒计时与任务记录，也不写入新的轮次或会话统计。`reality.streamHistory` 只作冻结兼容字段随旧存档往返，不产生当前写入。完整状态和最近 10 次完成/停止记录全部由独立页展示并写入独立页自己的 `localStorage`。每完成一轮，独立页都用同一 `sessionId` upsert 当前 `running/checkpoint` 会话，不额外新增一行；正常停止把这条记录覆盖为 `final`，`pagehide` 只作兜底，因此硬关闭至少仍保留上一完整轮。0 轮正常停止也可形成 final 记录。运行中的 iframe、定时器、限时、保活音频和独立页 DEBUG 设置不进入 `.bingo`。
- 独立页实际进入 `started` 后，通过受信同源消息把 UI 产生的本地日期 `YYYY-MM-DD` 交给打开它的主游戏页面；主游戏先做日期语义校验，再按 `reality.streamDailyReward.lastRewardDateKey` 原子发放首次 20🍎。该字段保留已经结算的最大本地日期；同日或更早日期不重复发放，只有严格更晚的现实日期首次 `started` 才能再次领取。弹窗创建、iframe `load`、本地轮次与页面存活都不能替代 `started` 门槛。
- 官方 iframe 或完整视频页会按浏览器自身策略使用当前可用于 B 站的 Cookie，并由 B 站来源脚本自行发出媒体、统计、历史或心跳请求。GitHub Pages 工具页受同源策略限制，不能读取 Cookie、跨域页面 DOM、真实播放器状态或响应，也没有实现 CORS 绕过；它只控制 URL、创建顺序、绝对计时和关闭。iframe 创建、`load`、窗口句柄、本地轮次和消息都不能证明真实播放、播完或增加计数。

### 17.3 一楼电脑：工作

- 工作面板按“背景选择器 → 苹果钟时长 → 待办”排列；待办可创建、编辑、标记完成/未完成和删除，数据写入 V12 存档。
- 苹果钟提供 25+5、50+10、90+15 三组“专注 + 休息”周期；状态保存 `focusEndsAt` 与 `cycleEndsAt` 两个绝对截止时间。
- 可选择已解锁明信片或一张已保存的奇迹合拍作为背景；启动后按 session 快照锁定 `{ kind, id }` 引用，不复制图片、标题或合成位图。
- 运行时使用全屏焦点 UI，把锁定的明信片或按构图数据动态重建的奇迹合拍以 `cover` 铺满背景并允许裁切，同时展示 `pose="stream"`、坐在电脑前陪伴的饼狗、待办、信息卡和可操作的游戏播放器控件；不再使用睡觉姿态表达专注。苹果钟专属容器裁去该 `stream` 帧顶部 2% 的杂边，房间中的同姿态不受影响。播放器展开时信息卡自动收缩，隐藏时恢复。
- 苹果钟可以取消；截止时间已到时必须完成，不能利用延迟 UI 取消绕过结果。
- 专注到点只切换到休息并提醒；休息到点完成整轮时才原子执行 `companionDays + 1`，并推进或结束活力七相伴日。重复 tick、未到点 tick 和截止前取消都不加天。
- 普通现实停留结算、待办 CRUD 与单独的待办到期通知不增加陪伴天数。
- 专注结束、整轮结束或已有到期时间的待办到期时，领域层签发稳定 notification effect，并记录已签发时间避免重复。

## 18. 通知、守候音频与 PWA

### 18.1 浏览器通知

- 只在用户点击“开启提醒”后调用 `Notification.requestPermission()`。
- 权限为 granted 时创建带稳定 `tag` 的系统通知；不支持、拒绝或构造失败时改用页内 toast。
- 页面计时器等待最近截止时间；`focus` 与 `visibilitychange` 后立即按绝对时间补检查。
- 页面完全关闭、浏览器冻结或设备休眠时不保证准点通知；本项目没有推送服务器或后台同步来绕过此限制。

### 18.2 守候音频

- 三个旅程入口的明确用户手势中创建或恢复一个 `AudioContext`。
- 单例 oscillator 为 10 Hz，gain 为 0.01；App 生命周期内复用。
- 运行期始终保持开启，不在状态栏暴露技术开关。
- App 卸载时停止 oscillator、断开节点并关闭 context。
- 这是保活的尽力措施，不能绕过浏览器后台冻结、系统节能或用户静音策略。

### 18.3 移动端屏幕常亮

- `useScreenWakeLock` 通过设备能力判断移动端，只在旅程运行且页面可见时请求 Screen Wake Lock；界面不展示输入设备识别等技术细节。
- 页面隐藏时释放，重新可见时再次请求；API 缺失或请求被拒绝时继续运行游戏。
- 屏幕常亮只减少前台熄屏，不能保证切到其他应用、锁屏或系统冻结后仍持续调度。

### 18.4 PWA 更新保护

- manifest 图标使用饼狗头像 PNG，包括 192、512 与 maskable 512；网页另有 favicon 32 和 Apple Touch 180。
- Service Worker 使用 prompt 更新模式。检测到新版本时自动下载当前缓存档，再提供安装并执行 reload。

## 19. DEBUG

- 可调未来活动时长与明信片、百万直拍、全站第一、旅行遇友、音乐好友五类概率。
- 快捷时长包括 10 秒、30 秒和历史 1 分 12 秒；新档默认选中 10 秒。
- 主游戏 DEBUG 不再设置刷播轮次时长。在线刷播工具以“大标题 5 次 + `SUperView`”单独解锁自己的 DEBUG，开启状态由独立页本地保存并可手动关闭；设置只影响独立页运行态且不写入游戏存档。
- DEBUG 不把意愿永久强制为 true；活力魔法仍是独立的游戏状态。
- “一键全收集”按当前三类收藏目录、好友目录和 24 件衣服目录即时写入记录，并把已无可售款式的 `shop.assetIds` 清空。
- “清空收集”清空三类收藏、好友记录与全部 saved looks，把衣服恢复为仅初始赠送 `cream-apple-cape`，并在同一 `companionDay` 按 `min(3, remaining)` 强制重建商店；当前 24 件目录因此得到 3 件商品。历史合拍保留拍摄时的轻量造型快照；合拍使用的明信片被清除后，只把相应 `postcardId` 置空。
- 两个批量动作都二次确认并报告收藏、好友与衣服的实际变更数量。
- 不维护专用全收集 `.bingo`。

## 22. 安全、隐私与可访问性

- 不保存凭证、微博 Cookie、GitHub PAT 或 B 站登录状态。
- 外链使用 `noopener noreferrer`；不可信文本不传给 `innerHTML`。
- 存档按严格 schema 重建白名单字段，摘要校验在迁移之前。
- 对话框打开时移入并限制焦点，Escape 关闭，关闭后恢复到仍存在的触发点。
- 颜色不是意愿拒绝、任务完成或分类解锁的唯一信息。
- 电子琴键具有音名、物理键映射和按下状态；只映射白键。
- 隐藏滚动条仍保留键盘和触摸滚动。
- 动画遵循 `prefers-reduced-motion`。
- 自动播放、通知与更新不将请求误写为成功；守候音频不再占用用户状态栏。
