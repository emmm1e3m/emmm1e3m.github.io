# 旅行饼狗网页完整实现方案

> 原始需求：[旅行饼狗开发纲要](specs/旅行饼狗开发纲要.md)
>
> 固定路径：`https://emmm1e3m.github.io/AllForSUXINHAO/TravellingBingo/`

## 1. 产品定义

“旅行饼狗”是一款以饼狗为主角的离线收集网页游戏。玩家在铲铲饼屋陪饼狗旅行、刷播、冲热、弹琴和睡觉，通过读条、Bingo 小任务、收藏与好友积累陪伴回忆；也可以切换到现实生活维度，用苹果钟和待办让游戏陪伴真实工作与学习。

产品原则：

- 房间是视觉主体，信息栏只解释当前语境与可执行动作。
- 饼狗有自己的旅行、电脑和音乐意愿；拒绝是可见状态，不是隐藏入口。
- 五类饼屋读条共享二次确认、绝对时间、取消、领取和存档恢复规则；现实苹果钟使用独立的绝对时间完成流程。
- 🍎 的获得与花费都有明确来源；金额一律显示为 `N🍎`。
- 收藏与好友以第一次相遇为惊喜，不提前展示灰色占位、未解锁分类或永久总数。
- 游戏状态与第三方播放器、浏览器通知等外部能力严格分层；不可观测的外部状态不得被伪装成成功。
- `.bingo` 由玩家自己保管，不上传、不登录。

## 2. 运行与公开边界

- 游戏固定部署在 `/AllForSUXINHAO/TravellingBingo/`；根首页只提供入口。
- Vite `base`、PWA `id`、`start_url`、`scope` 与导航回退均使用该子路径。
- 游戏不需要后端、数据库、排行榜、支付、广告、统计或用户跟踪。
- 首次在线访问并缓存应用外壳后，标题页、房间、计时、领奖和存档可离线使用；第三方 B 站 iframe 与未缓存高清图不承诺离线可用。
- 运行时不调用 B 站收藏夹 API，也不跨域抓取微博图片。内容目录在构建期固化为同源 JSON。
- Pages 只上传隔离组装的 `_site/`，不公开 `docs/`、`research/`、`resources/raw/`、源码、浏览器状态或抓取凭证。

## 3. 主流程

```text
根首页入口
  → 标题页
      ├→ 显式检查新布置
      ├→ 输入称呼并开始新旅程
      └→ 选择 .bingo → 摘要预览 → 确认导入
  → 铲铲饼屋
      ├→ 房间空白 → 当前任务与意愿概览
      ├→ 设施 → 对应信息栏
      ├→ 读条活动 → 二次确认 → running / ready
      │    ├→ ↩️ 取消：不计天、不退款、不发奖
      │    ├→ 速度魔法：立即 ready
      │    └→ 领取：陪伴天数 +1
      ├→ 收藏墙 → 收藏 / 好朋友 / 视频详情
      ├→ 唱片机 → 持久播放器
      ├→ 电子琴 → 四排琴键
      ├→ ℹ️ → 简洁的“铲铲饼屋的小纸条”
      └→ 右下维度按钮
           ├→ 游戏维度
           └→ 现实维度 → 数据 / 工作
                ├→ 苹果钟完成专注与休息整轮：陪伴天数 +1
                └→ 返回结算：只结算 🍎，不加天
  → 离开房间 → 浏览器缓存保留当前进度 → 返回标题页
```

## 4. 标题页、更新检查与称呼

- 标题页固定提供“新存档”“从缓存存档继续”“加载本地存档”和显式“检查新布置”。
- 称呼去除首尾空白，接受 1–16 个非空 Unicode 字符；不合格时在输入框附近说明。
- 导入预览显示文件名、导出时间、游戏版本、称呼、陪伴天数、`N🍎`、收藏数量和当前活动。
- 文件选择只创建待确认预览，不立即覆盖内存状态。
- “检查新布置”调用当前 Service Worker registration 的 `update()`；没有 Service Worker、尚未注册或网络失败时显示相应状态。
- 检查结果使用临时提示，不作为固定页面元素；检测到新 Service Worker 时自动下载当前缓存档，再提供安装更新。
- 连续激活标题五次后可输入 `TravellingBingo` 解锁 DEBUG；它是隐藏入口，不是安全边界。

## 5. 视觉、字体与通用文案

### 5.1 字体

| 用途                                   | 字体       | 公开文件                              |
| -------------------------------------- | ---------- | ------------------------------------- |
| 游戏标题、页面大标、房间设施、收藏分类 | 可画乐融融 | `assets/fonts/kehua-lerongrong.woff2` |
| 正文、按钮、任务、日期与小型 UI        | 可画奶糖体 | `assets/fonts/kehua-naitang.woff2`    |

字体源位于 `resources/raw/travelling-bingo/fonts/`，公开页面只发布项目字符子集 WOFF2。日期中的“月”等汉字必须包含在子集并使用同一正文字体。

### 5.2 货币与固定文案

- 可见金额统一为 `N🍎`，例如 `3🍎`、`还差 2🍎`、`朋友送来 3🍎`。
- 不显示“X 个苹果”“补充·X个苹果”“按钮仍然可以按”等元叙述。
- “苹果”文字只用于角色口味、道具名称和“今天也要好好吃苹果”等自然语句。
- 冰箱标题为“补充道具”，不重复“为冰箱”。
- 衣架正文为“什么样的搭配最合适呢？”。
- 刷播说明为“在电脑前好好陪伴，加速百万直拍的达成。”。
- 空收藏墙文案为“惊喜会在相遇时悄悄出现。”。

### 5.3 控件

- 触控目标至少 `44 × 44 CSS px`，具备焦点圈、按压反馈和可理解的可访问名称。
- 房间设施用文字标签，不要求玩家猜抽象图标。
- 顶栏中心“今天也要好好吃苹果”单行真正居中；各 HUD 文字使用同一字号等级。
- 信息栏顶行只保留语境标签；点击房间空白即可回到任务与意愿概览。
- 设施信息使用常规左对齐的读条卡层级，不复用大型居中结果页布局。
- `ℹ️` 按当前维度打开简洁说明；游戏维度不扩写成长篇设施或价格手册，现实维度需要说明苹果钟与 🍎 结算。

## 6. 房间母版与布局

### 6.1 唯一母版

```text
resources/raw/travelling-bingo/generated/chan-chan-house-master.png
```

母版为用户提供的 1098 × 1433 RGBA 原图。应用目录 `AllForSUXINHAO/TravellingBingo/` 下的公开派生图沿用兼容文件名：

```text
public/assets/game/chan-chan-house-v2-768.webp
public/assets/game/chan-chan-house-v2-1098.webp
```

处理只允许等比缩放和无损 WebP 编码；不得裁切、重绘、补画、改变构图或丢失透明通道。

### 6.2 桌面与移动布局

- 顶栏、房间和信息栏共享页面 inset。房间左侧与顶栏左侧对齐，信息栏右侧与顶栏右侧对齐。
- 房间到信息栏的横向 gap 与顶栏到内容的纵向 gap 使用同一紧凑 token。
- 房屋背景铺满横向房间卡，纵向透明房图只作为唯一交互坐标层，不再叠加内侧长方形底板。
- 房屋与信息栏不做展开/收起动画；切换不同信息内容时使用轻量 keyed 入场动画。
- 手机上信息栏变为单列全宽内容；关闭、取消、维度切换和播放器控制必须留在视口或可滚动范围内。
- 隐藏滚动条不等于禁止滚动；滚轮、触摸、方向键和 PageUp/PageDown 仍要工作。

## 7. V5 领域状态

精确类型以 `src/domain/game/types.ts` 为准，核心形状为：

```ts
interface GameStateV5 {
  schemaVersion: 5
  profile: {
    createdAt: number
    debug: boolean
    displayName: string
    companionDays: number
  }
  economy: { apples: number }
  inventory: Record<ItemId, number>
  collections: Record<string, CollectionEntry>
  friends: Partial<Record<FriendId, FriendEntry>>
  activeActivity: ActivityRun | null
  pet: PetState
  tasks: TaskBoard
  gameBalance: GameBalance
  statistics: GameStatistics
  random: PersistentRandomState
  world: 'game' | 'reality'
  player: {
    effects: { vitality: VitalityEffect | null }
  }
  reality: {
    nextStaySequence: number
    activeStay: RealityStay | null
    pendingSettlement: RealitySettlement | null
    todos: Record<string, TodoItem>
    pomodoro: PomodoroState
  }
  musicPlayer: MusicPlayerState
}
```

`ActivityRun` 保存 `runId`、种类、`startedAt`、`endsAt`、`rewardSeed`、完整 `rewardPlan`、补给和幸运苹果快照。当前面板、弹窗、琴键按下状态、奖励 UI、走路和日夜动画不写入存档。

### 7.1 目录不是存档

存档不保存：

- 收藏分类总数、总收藏数或完成百分比；
- 全站第一的“下一项”索引；
- 分类解锁数组；
- 好友总数与图片元数据；
- B 站标题、作者、海报或视频目录副本。

完成度、可见分类、下一项全站第一和播放器展示信息均由“当前目录 + 存档 ID”派生。目录增加项目时旧档无需重置。

## 8. `.bingo` 导入、导出与迁移

### 8.1 外层格式

- UTF-8 JSON，扩展名 `.bingo`，MIME `application/octet-stream`。
- 外层包含格式标识、封套版本、`gameVersion`、导出时间、业务 payload 与 SHA-256 摘要。
- 最大 1 MiB；未知字段由严格 Zod schema 拒绝。
- SHA-256 只用于发现损坏或误改，不是签名或加密。

### 8.2 V5 缓存与导出

- 日常成功动作同步写入版本化 `localStorage` 单槽缓存；缓存不可用时才注册离开提醒。
- 通过“新存档”或“加载本地存档”覆盖缓存前先下载旧缓存；首次获得新的全站第一或认识新朋友构成关键节点，每到关键节点、每隔三天、检测到网页更新时自动请求 `.bingo` 备份。
- 新导出只写 `schemaVersion: 5`，`gameVersion: 0.5.0-demo.1`。
- 用户名、天数、活动、任务、随机序列、收藏、好友、七种道具、魔法、现实、待办、苹果钟、播放列表与播放器设置完整往返。
- 正常文件名为 `travelling-bingo-YYYYMMDD-HHmmss.bingo`；DEBUG 在扩展名前加 `-debug`。
- 离开房间只返回标题页，不清除浏览器缓存；`.bingo` 继续作为显式备份与跨浏览器导入格式。

### 8.3 V1–V5 导入顺序

1. 先按文件原始 payload 校验摘要。
2. 用冻结的严格 V1–V5 schema 解析。
3. 逐代迁移到 V5。
4. 规范非 DEBUG 状态未来活动的默认平衡。
5. 用当前目录协调可安全修复的旧引用。
6. 最终语义校验通过后才允许确认进入。

迁移不变量：

- 旧活动的 `startedAt`、`endsAt`、`rewardSeed`、`rewardPlan` 原样保留。
- V5 默认 10 秒只影响迁移之后新开始的活动。
- 历史用户名缺失时使用兼容称呼；陪伴天数由旧领取统计推导。
- V3 活动、好友与意愿字段保留；V4/V5 新字段使用安全初值。
- V5 不允许退役的 `greet-bingo` 留在当前任务板；迁移按当前任务目录替换，并保持任务 PRNG 可重现。
- V5 任务板以 `completedAt` 记录最后一项完成时间；完成后保留到下一个本地自然日再刷新。
- 已失效的苹果钟明信片背景可以清空；非法奖励组合、未知活动奖励或篡改时间必须拒绝，不能被协调步骤静默删除。

## 9. 五类读条与陪伴天数

```ts
BASE_ACTIVITY_DURATION_MS = 10_000
```

| 活动 | 入口     | 意愿     | 补给       | 位置     | 主要结果                |
| ---- | -------- | -------- | ---------- | -------- | ----------------------- |
| 旅行 | 房门     | 旅行     | 旅行便当   | 房外     | 好友道具或明信片        |
| 刷播 | 二楼电脑 | 电脑     | 信号耳机   | 电脑前   | 百万直拍                |
| 冲热 | 二楼电脑 | 电脑     | 热度工具箱 | 电脑前   | 全站第一                |
| 弹琴 | 电子琴   | 音乐     | 无         | 电子琴前 | 已认识好友可能赠 2–4🍎  |
| 睡觉 | 床铺     | 始终允许 | 无         | 床上     | 1🍎、刷新意愿、日夜转场 |

- 五类开始前都显示时长、消耗、可能结果和取消语义。
- `endsAt - 1 ms` 仍是 running；从 `endsAt` 起为 ready。
- 计时视图每秒刷新，页面重新聚焦或可见时按系统时间重算；长 `setTimeout` 不是权威时钟。
- 每次成功领取当前 `runId`，`companionDays` 恰好 `+1`。
- 取消必须携带当前 `runId`，避免旧确认清除新任务。
- 取消不计天、不发奖、不退款，也不回滚开始活动时推进的奖励随机序列。
- 陪伴天数的另一来源是现实苹果钟完成专注与休息整轮；普通现实停留结算和待办不属于陪伴日。

## 10. 意愿、状态栏与两种魔法

- 意愿键为 `travel | computer | music`；刷播和冲热共享 `computer`。
- 每轮至少有一组非睡眠活动可做；睡觉领取后刷新意愿。
- 不愿意入口视觉变淡并带 `aria-disabled`，但保留点击以显示拒绝说明或活力魔法确认。
- 顶部状态栏使用统一字号与控件样式，纯文字单行完整显示当前活动、疲劳或活力剩余相伴日；不显示狗 emoji、守候音频或检查更新按钮，也不再套独立黑边胶囊。

### 10.1 瓶装速度魔法

- 道具 ID：`bottled-speed-magic`，价格 3🍎，emoji ⚡。
- 仅当前活动处于 running 时可用。
- 二次确认后消耗一瓶，将当前活动 `endsAt` 原子改为使用时间；奖励计划不变。
- 已 ready、runId 不匹配、没有道具或时间非法时不消耗。

### 10.2 瓶装活力魔法

- 道具 ID：`bottled-vitality-magic`，价格 12🍎，emoji ✨。
- 使用后把旅行、电脑、音乐意愿全部设为真并清除疲劳。
- `activatedOnCompanionDay` 记录生效日，`expiresAfterCompanionDay` 为其后第七个相伴日的 exclusive 边界。
- 领取饼屋活动或完成苹果钟专注与休息整轮都会推进相伴日。有效期间睡觉刷新不能把意愿改回 false；第七日由相应完成动作清除 effect，并按持久偏好序列恢复当日意愿。
- 已有有效效果、库存不足、达到天数上限或当前无需使用时拒绝且不消耗。

## 11. Bingo 与 🍎 经济

- 新游戏和迁移后都保持三条活动任务；同一板不重复模板。
- 单条完成立即发放任务快照中的 🍎；三条全部完成后保留全完成板，并记录 `completedAt`。
- 到完成后的下一个本地自然日才刷新新板；跨日后的第一个领域动作先刷新，再尝试命中新任务。
- V5 不再签发“和饼狗打个招呼”；可验证事件包括房间走访、收藏查看、琴键、唱片机、收藏播放器和舞台测试。
- 唱片机与收藏播放器事件只代表用户主动请求对应 BV，不能代表 iframe 已加载、播放或播完。

经济流：

```text
Bingo 小任务 ───────────────────→ 🍎
睡觉完整读条 ──────────────────→ 1🍎
弹琴完整读条 + 已认识好友来访 ─→ 2–4🍎
现实维度完整十分钟 ───────────→ 结算基数 1🍎
🍎 ───────────────────────────→ 七种冰箱道具 / 明确的意愿鼓励
```

| 道具           | 价格 | 用途                      |
| -------------- | ---: | ------------------------- |
| 🍱普通旅行便当 |  3🍎 | 启动旅行                  |
| 🍎苹果旅行便当 |  5🍎 | 启动旅行，遇友概率 +0.15  |
| 🎧信号耳机     |  4🍎 | 启动刷播                  |
| 🧰热度工具箱   |  7🍎 | 启动冲热                  |
| 🍀幸运苹果     |  6🍎 | 对应收藏概率 +10 个百分点 |
| ⚡瓶装速度魔法 |  3🍎 | 立即完成当前读条          |
| ✨瓶装活力魔法 | 12🍎 | 七个相伴日全部意愿为真    |

## 12. 概率、好友与收藏顺序

```ts
DEFAULT_GAME_BALANCE = {
  activityDurationMs: 10_000,
  probabilities: {
    postcard: 0.65,
    millionShot: 0.4,
    siteFirst: 0.1,
    travelFriend: 0.2,
    musicFriend: 0.2,
  },
}
```

- 所有判定使用 `roll < chance`；0 永不命中，1 必定命中。
- 幸运苹果只把当次对应收藏概率加 `0.10`（10 个百分点），苹果旅行便当只影响旅行遇友概率，均封顶 1。
- 已集齐分类或基础概率为 1 时，不能浪费幸运苹果。

旅行顺序：

1. 判定 `travelFriend`。
2. 命中后选择好友，签发固定道具礼物并停止。
3. 没命中好友时才判定明信片。
4. 命中明信片后从未拥有项随机选择。

音乐好友：

- 只读取活动开始时已经认识的好友集合。
- 空集合时不判定来访。
- 命中后从已认识好友选择一位，按身份固定赠 2–4🍎。

## 15. 持久 B 站播放器与列表

### 15.1 静态目录

- 百万直拍收藏夹 ID：`1130054521`。
- 全站第一收藏夹 ID：`3489626721`。
- 唱片机内置曲目为当前八项中的最新七项全站第一，即 Talk WORTHY? Talk DIRTY! 至 POWER；运行时不抓取收藏夹。
- 每个收藏条目从自身 `metadata.video` 读取 BVID、标题、作者、发布时间与来源链接，不维护第二套手写映射。

### 15.2 播放器生命周期

- `BilibiliPlayerProvider` 只持有受控业务状态与唯一运行态；唯一 `PersistentPlayerDock` 放进当前真正可交互的房间、收藏墙或苹果钟焦点分支。
- 选曲或详情挂载后立即请求 `autoplay=1`；iframe 允许 autoplay/fullscreen/picture-in-picture。
- 切换信息内容、关闭收藏详情或切换维度不卸载当前 iframe；玩家可“隐藏画面”保持连接，也可“停止播放”。
- 播放请求记录来源：唱片机、收藏 ID、播放列表或直接请求。

### 15.3 播放设置与列表

- V5 状态保存播放列表、顺序、当前列表、当前 BV/索引和列表/单曲/随机模式。
- 解析器接受逐行 BV 号或完整 Bilibili 视频链接，规范名称、去重、列出被拒绝行；`b23.tv` 这类不含 BV 的短链接必须先展开。
- 手动切歌与视频结束策略分开：列表和单曲模式的上一首/下一首都移动到相邻项，随机模式主动选择其他项；只有结束策略下单曲模式才重播当前项。
- 唱片机信息栏已挂载播放列表编辑器，可在内置“全站第一”和已保存曲库间切换。
- 从内置曲库提交名称与 BV 列表时创建并选中新列表；选中已有列表后提交会更新现有列表。列表和播放设置随 V5 存档往返。

### 15.4 跨域限制

B 站 iframe 不向父页面提供可靠的播放状态接口。网页不能确认：

- 是否真的开始自动播放；
- 是否正在暂停；
- 真实播放位置；
- 视频是否结束。

GitHub Pages 是静态托管，浏览器又不能伪造 B 站 Referer；API 与带签名的 DASH/MP4 流不能从当前 Pages Origin 稳定直取。构建时固化的流地址也会很快过期，因此不引入未知第三方代理，继续使用官方 iframe。当前策略为：

- `autoplay=1` 是请求，不是成功回执；浏览器可能要求用户在 iframe 内操作。
- 已知视频在 iframe 加载后按静态 `durationSeconds` 尽力触发续播；无法得到可靠结束事件的视频不会假装精确。
- 任务只记录“请求打开这个 BV”。

## 16. 现实生活维度

### 16.1 进入、离开与结算

- 只允许满足 `(hover: hover) and (pointer: fine)` 的 PC 主输入能力进入；不使用 UA 品牌名单或窗口宽度启发式。打开确认和最终提交前各检查一次。
- 非 PC 恢复停留在现实维度的存档时不篡改存档，只显示不可关闭的返回入口，显式 `reality/leave` 后照常结算。
- `reality/enter` 记录 `stayId` 与绝对 `enteredAt`，并把 `world` 切为 `reality`。
- `reality/leave` 使用当前时间计算 `floor((leftAt - enteredAt) / 10min)`，返回游戏并建立待决结算。
- 玩家必须回答“是的🥰”或“没有🥺”。前者获得全额，后者获得 `floor(full / 2)`。
- 结算有稳定 `stayId`；重复、过期或不匹配请求不会再次发奖。
- 现实停留和待决结算均写入存档。

### 16.2 二楼电脑：数据

固定说明：

```text
认真刷播：在该页面中直接开始刷播（无需但是建议加入运行组）
全力冲热：在该页面中启动冲热任务（需要加入运行组，与最新版插件配合使用）
```

- 页面直接从刷播与冲热行动卡开始，不显示整块“现实生活”介绍。
- “冲热刷播，奖品多多”的“前往”打开 `https://www.weibo.com/u/7878664767`，使用 `noopener noreferrer`。

### 16.3 一楼电脑：工作

- 待办位于明信片选择器之前，可创建、编辑、标记完成/未完成和删除；数据写入 V5 存档。
- 苹果钟提供 25+5、50+10、90+15 三组“专注 + 休息”周期；状态保存 `focusEndsAt` 与 `cycleEndsAt` 两个绝对截止时间。
- 可选择已解锁明信片作为背景；启动后按 session 快照锁定收藏 ID，不复制图片或标题。
- 运行时使用全屏焦点 UI，展示明信片、陪伴饼狗、待办、信息卡和唯一可交互播放器；播放器展开时信息卡自动收缩，隐藏时恢复。
- 苹果钟可以取消；截止时间已到时必须完成，不能利用延迟 UI 取消绕过结果。
- 专注到点只切换到休息并提醒；休息到点完成整轮时才原子执行 `companionDays + 1`，并推进或结束活力七相伴日。重复 tick、未到点 tick 和截止前取消都不加天。
- 普通现实停留结算、待办 CRUD 与单独的待办到期通知不增加陪伴天数。
- 专注结束、整轮结束或已有到期时间的待办到期时，领域层签发稳定 notification effect，并记录已签发时间避免重复。

## 17. 通知、守候音频与 PWA

### 17.1 浏览器通知

- 只在用户点击“开启完成提醒”后调用 `Notification.requestPermission()`。
- 权限为 granted 时创建带稳定 `tag` 的系统通知；不支持、拒绝或构造失败时改用页内 toast。
- 页面计时器等待最近截止时间；`focus` 与 `visibilitychange` 后立即按绝对时间补检查。
- 页面完全关闭、浏览器冻结或设备休眠时不保证准点通知；本项目没有推送服务器或后台同步来绕过此限制。

### 17.2 守候音频

- 三个旅程入口的明确用户手势中创建或恢复一个 `AudioContext`。
- 单例 oscillator 为 10 Hz，gain 为 0.01；App 生命周期内复用。
- 运行期始终保持开启，不在状态栏暴露技术开关。
- App 卸载时停止 oscillator、断开节点并关闭 context。
- 这是保活的尽力措施，不能绕过浏览器后台冻结、系统节能或用户静音策略。

### 17.3 PWA 更新保护

- manifest 图标使用饼狗头像 PNG，包括 192、512 与 maskable 512；网页另有 favicon 32 和 Apple Touch 180。
- Service Worker 使用 prompt 更新模式。检测到新版本时自动下载当前缓存档，再提供安装并执行 reload。

## 21. 安全、隐私与可访问性

- 不保存凭证、微博 Cookie、GitHub PAT 或 B 站登录状态。
- 外链使用 `noopener noreferrer`；不可信文本不传给 `innerHTML`。
- 存档按严格 schema 重建白名单字段，摘要校验在迁移之前。
- 对话框打开时移入并限制焦点，Escape 关闭，关闭后恢复到仍存在的触发点。
- 颜色不是意愿拒绝、任务完成或分类解锁的唯一信息。
- 电子琴键具有音名、物理键映射和按下状态；只映射白键。
- 隐藏滚动条仍保留键盘和触摸滚动。
- 动画遵循 `prefers-reduced-motion`。
- 自动播放、通知与更新不将请求误写为成功；守候音频不再占用用户状态栏。
