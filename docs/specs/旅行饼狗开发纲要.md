# 旅行饼狗开发纲要

## 目标与路径

复刻《旅行青蛙》的陪伴与离线收集感，制作完整、美观、有趣且自洽的粉丝向网页游戏“旅行饼狗”。游戏本体固定在：

```text
/AllForSUXINHAO/TravellingBingo/
```

根首页只增加跳转入口；`AllForSUXINHAO/` 只保留 `TravellingBingo/`。游戏不依赖游戏后端、账号、登录、数据库或运行时收藏夹 API；`.bingo` 是玩家持有的权威存档。

## 饼狗与铲铲饼屋

![饼狗形象参考](../../resources/raw/travelling-bingo/references/outline/image.png)

饼狗是 TOP 登陆少年组合成员苏新皓的卡通形象，是一只喜欢吃苹果、戴着苹果头套的小狗。它不是无条件执行命令的按钮，会分别决定是否想旅行、做电脑活动或弹琴；刷播和冲热共享电脑意愿。

房屋唯一生产母版为：

```text
resources/raw/travelling-bingo/generated/chan-chan-house-master.png
```

它是用户提供的 1098 × 1433 RGBA 原图。网页只允许等比缩放和无损 WebP 编码，不得重绘、裁切或改变透明通道、两层结构、家具、人物、兔子与树冠。

房间设施：

- 床铺：开始睡觉；饼狗中心点 `(225, 300)`。
- 二楼电脑：游戏维度开始刷播/冲热，现实维度打开“数据”；中心点 `(504, 409)`。
- 衣架：打开“奇迹饼狗”，正文为“什么样的搭配最合适呢？”；中心点 `(387, 675)`。
- 电子琴：C4–B6 三个八度、三排琴键；中心点 `(257, 1103)`。
- 一楼电脑：现实维度打开“工作”；中心点 `(420, 1172)`。
- 冰箱：使用 🍎 补充七种道具；中心点 `(633, 951)`。
- 唱片机：静态曲目、持久 B 站播放器与播放设置；中心点 `(783, 1030)`。
- 收藏墙：明信片、百万直拍、全站第一和好朋友；中心点 `(1053, 673)`。
- 房门：开始旅行；中心点 `(980, 1176)`。

房间右上角的 `ℹ️` 打开简洁说明，角标精确为“铲铲饼屋的小纸条”；不得扩写为长篇设施与价格手册，详细价格只留在冰箱。设施信息使用常规左对齐的读条卡层级，不复用大型居中结果页布局。活动中左下角用 `↩️` 请求取消，右下角切换旅行饼狗/现实生活维度。点击空白区域显示当前任务与意愿概览；信息栏右上角可收起。组件切换可以有轻量内容动画，但房屋和信息栏本身不做展开/收起动画。

## V4 活动与陪伴日

- 旅行、刷播、冲热、弹琴、睡觉都是读条任务，V4 新活动默认 1 分 12 秒。
- 开始前均在信息栏二次确认；每次成功领取结果后，陪伴天数增加一天。现实维度的一轮苹果钟首次到点完成也增加一天。
- running 与 ready 都可取消。取消不增加天数、不发放奖励，也不返还开始时已经消耗的补给或幸运苹果。
- 进行中活动保存 `startedAt`、`endsAt`、`rewardSeed` 和完整 `rewardPlan`。之后改变默认时长不得重算旧活动。
- 睡觉完成后得 1🍎、刷新意愿并播放日夜转场；饼狗必须在床上。
- 拒绝的活动入口变暗并使用 `aria-disabled`，但保留点击反馈；点击不扣资源、不推进随机序列、不打开普通启动确认。

冰箱新增：

- ⚡瓶装速度魔法，8🍎：在读条进行中确认使用，消耗一瓶并让当前任务立刻完成。
- ✨瓶装活力魔法，12🍎：确认使用后，未来七个相伴日内三组意愿都为真。

活力按陪伴天数而非自然日计算。领取饼屋活动或首次完成到点苹果钟都会推进一天；苹果钟推进到第七日时清除效果并恢复当日偏好。效果有效或本来无需使用时不能重复消耗。

## Bingo、🍎 与 DEBUG

- 房间保持三条 Bingo 小任务；每条完成立即得 🍎，整板完成后刷新。
- 任务只使用能够由网页直接验证的事件。播放器任务表示玩家请求打开对应 BV，不声称第三方 iframe 真正播放或播完。
- 所有可见金额统一为 `N🍎`；“苹果”文字只用于角色口味、道具名称和“今天也要好好吃苹果”等自然语句。
- DEBUG 可调未来任务时长和五类概率，但不默认强制全部意愿。
- 不维护预制全收集存档。DEBUG 提供“一键全收集”和“一键撤销全部收集”，两者都同时处理收藏与好友。

## 收藏、概率与好友

### 明信片

来源：[Bilibili Toy 明信片归档](https://www.bilibili.com/toy/preview/preview_5SdX8Yet/index.htm)。

- 当前目录为 100 张人工筛选的真实照片。
- 旅行未遇见朋友时，以 65% 基础概率判断明信片。
- 命中后从当前未拥有集合随机选取，不重复。

### 百万直拍

来源：[Renaissance 苏新皓微博](https://weibo.com/7760819929?refer_flag=1001030103_) 与 [百万直拍收藏夹](https://space.bilibili.com/1210409821/favlist?fid=1130054521&ftype=create)。

- 当前目录为 30 张，基础概率 40%，随机从未拥有集合选取。
- 每张海报关联静态 BVID、标题、作者和发布时间。
- `Survivors` 使用正确的第二张红白纪念海报。

### 全站第一

来源：[全站第一收藏夹](https://space.bilibili.com/1210409821/favlist?fid=3489626721&ftype=create)。

![八项全站第一总览](../../resources/raw/travelling-bingo/site-firsts/all-site-no1-overview.png)

- 当前目录为 8 项，基础概率 10%，不使用保底。
- 严格从旧到新不重复获得：Dynamite → Talk WORTHY? Talk DIRTY! → Make A Wish → Dawn in my soul → 愿与愁 → 囍 → Hey Mama → POWER。
- POWER 只是当前最新项，不是永久末项；存档不保存“下一项”指针。

### 好朋友

旅行先判断朋友，再判断明信片；两者不能同时出现。朋友旅行相遇时赠固定道具。弹琴结束只能从已经认识的朋友中召回来访者，赠送 2–4🍎，不能通过音乐解锁新朋友。

收藏墙只显示已获得内容；首次获得或相遇后才出现对应分类。空墙文案为“惊喜会在相遇时悄悄出现。”，不显示总数进度、灰色占位或排序说明。朋友卡使用真实角色图铺满裁切，不显示累计收到的 🍎。

## 三排电子琴

- 覆盖 C4–B6 三个完整八度，共 36 个半音，按八度分为三排；中排 C 为 C5。
- 鼠标、触摸可弹全部琴键；物理键盘只映射白键。
- 白键映射为 C4 排 `Z X C V B N M`、C5 排 `A S D F G H J`、C6 排 `Q W E R T Y U`。
- 提示语为：“从 A5 G5 G5 B5 G5 E5 G5 G5 B4 C5，D5 C5 A5 A5 A5 B5 B5 B5 B5 C6 开始试试”。
- 使用 Web Audio 模拟钢琴音色；弹琴读条期间仍可自由交互，琴面板不能产生横向滚动条。

## B 站播放器

- 收藏和唱片机使用构建期静态视频目录；运行时不请求收藏夹 API。
- 选择曲目或打开视频详情即发送 `autoplay=1` 请求；不提供“打开/关闭播放器”的详情按钮。
- 唱片机与详情共用持久 iframe。收起信息栏或切换维度不自动卸载；玩家可明确停止。
- 播放状态保存当前 BV、主动设置的起播秒数、播放列表和列表/单曲/随机模式。
- 唱片机信息栏可在“百万直拍精选”和已保存的自定义曲库间切换；输入解析接受一行一个 BV 号或完整 Bilibili 视频链接，去除重复项并列出无法解析的行。
- 从内置精选提交会创建并选中命名列表；选中已有列表后提交会保存更新，列表与播放设置随 V4 存档往返。
- B 站 iframe 跨域，父页面不能可靠读取真实暂停、进度或结束，也不能确认自动播放是否成功。因此不承诺结束后自动续播；列表模式只决定玩家主动切歌时的下一项。

收藏/视频详情整体比例为 PC 与手机横屏 16:9、手机竖屏 9:16。媒体区使用 `cover`，点击海报或明信片后进入 `contain` 完整预览，并可下载本地。

## 现实生活维度

- 进入现实维度时记录绝对时间；每停留完整 10 分钟，返回时结算基数增加 1🍎。
- 返回游戏必须回答“是的🥰”或“没有🥺”；前者获得全额，后者获得向下取整的一半。
- 二楼“数据”提供刷播、冲热说明和运行组链接：`https://www.weibo.com/u/7878664767`。具体使用步骤保留明确的待开发占位，不伪装成已接入真实运行任务。
- 一楼“工作”提供 5、25、50 分钟苹果钟、已解锁明信片背景和持久化待办 CRUD。
- 苹果钟按绝对 `endsAt` 完成。首次权威完成时 `companionDays + 1`，并同步推进活力七相伴日；重复 tick、未到点、截止前取消、普通现实停留结算、待办操作或单独的待办到期均不增加天数。浏览器支持且用户授权时请求系统通知；否则使用页内提示。

## V4 存档

- 新导出业务 payload 为 `schemaVersion: 4`，封套 `gameVersion: 0.4.0-demo.1`。
- 导入支持严格 V1、V2、V3、V4。顺序是：原始摘要校验 → 历史 schema 解析 → 迁移至 V4 → 规则规范化 → 当前目录协调 → 最终语义校验。
- V1–V3 的进行中活动保留原始绝对时间和奖励计划；旧任务不会因 V4 默认 72 秒而被改写。
- V4 保存用户名、陪伴天数、🍎、七种道具、收藏、好友、任务、意愿、当前活动、魔法、现实停留/结算、待办、苹果钟、播放列表与播放器设置。
- 不保存收藏总数、分类解锁、全站第一指针、好友总数或视频元数据。目录追加后旧档自然把新 ID 视为未拥有。
- 离开房间或安装 PWA 更新前沿用两阶段保存确认；期间产生新进度时，旧确认不能继续。

## PWA 与浏览器能力边界

- 标题页有显式“检查新布置”，房间状态栏也可再次检查。检查调用 Service Worker `registration.update()`，但不会绕过未保存进度保护自动刷新。
- 网页提供可暂停的 10 Hz、增益 0.01 守候音频，只在明确用户手势后创建。它是尽力保活，不能绕过浏览器或操作系统后台冻结。
- 通知必须由用户主动授权；页面完全关闭、系统休眠或后台被冻结时不保证准点弹出，重新聚焦后按绝对时间补检查。
- 第三方有声自动播放可能被浏览器拦截；UI 必须提供真实状态说明和来源页回退。
- 网页、Apple Touch 与 PWA 图标统一使用饼狗头像 PNG。

## 验收入口

```powershell
npm run verify
npm run build
npm run site:assemble
npm run site:verify
npm run test:e2e
```

`npm run verify` 不包含 Playwright；真实浏览器流程必须单独运行 `npm run test:e2e`。跨域播放器验收只检查请求 URL、iframe 持久性、任务事件和存档状态，不检查父页面无法观测的真实播放状态。
