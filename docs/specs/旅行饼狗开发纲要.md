# 旅行饼狗开发纲要

## 目标与路径

复刻《旅行青蛙》的陪伴与离线收集感，制作完整、美观、有趣且自洽的粉丝向网页游戏“旅行饼狗”。游戏本体固定在：

```text
/AllForSUXINHAO/TravellingBingo/
```

根首页只增加跳转入口；`AllForSUXINHAO/` 只保留 `TravellingBingo/`。游戏不依赖游戏后端、账号、登录、数据库或运行时收藏夹 API；浏览器缓存是日常主存档，玩家持有的 `.bingo` 用于备份和跨浏览器导入。

## 饼狗与铲铲饼屋

![饼狗形象参考](../../resources/raw/travelling-bingo/references/outline/image.png)

饼狗是 TOP 登陆少年组合成员苏新皓的卡通形象，是一只喜欢吃苹果、戴着苹果头套的小狗。它不是无条件执行命令的按钮，会分别决定是否想旅行、做电脑活动或弹琴；刷播和冲热共享电脑意愿。

房屋唯一生产母版为：

```text
resources/raw/travelling-bingo/generated/chan-chan-house-master.png
```

它是用户提供的 1098 × 1433 RGBA 原图。网页只允许等比缩放和无损 WebP 编码，不得重绘、裁切或改变透明通道、两层结构、家具、人物、兔子与树冠。

桌面横向房间区域内用 `contain` 居中显示这张纵向母版，不拉伸、不裁切；母版以外的左右空间保持透明留白，不绘制内侧竖向底板。交互热点始终相对实际图片舞台定位。

房间设施：

- 床铺：开始睡觉；饼狗中心点 `(225, 300)`。
- 二楼电脑：游戏维度开始读条刷播/冲热，现实维度分别打开“刷播”和“冲热（开发中）”；饼狗中心点均为 `(504, 409)`。
- 衣架：打开“奇迹饼狗”，正文为“什么样的搭配最合适呢？”；中心点 `(387, 675)`。
- 电子琴：C3–B6 四个八度、四排琴键；中心点 `(257, 1103)`。
- 一楼电脑：现实维度打开“工作”；中心点 `(420, 1172)`。
- 冰箱：使用 🍎 补充七种道具；中心点 `(633, 951)`。
- 唱片机：静态曲目、持久 B 站播放器与播放设置；中心点 `(783, 1030)`。
- 收藏墙：明信片、百万直拍、全站第一和好朋友；中心点 `(673, 1053)`。
- 房门：开始旅行；中心点 `(980, 1176)`。

房间右上角的 `ℹ️` 打开当前维度的简洁说明；详细价格只留在冰箱。设施信息使用常规左对齐的读条卡层级，不复用大型居中结果页布局。`ℹ️`、活动中的 `↩️` 与维度切换 `🔃` 都放在横向房间区域角落；切换前先介绍并确认。点击空白区域显示当前任务与意愿概览。

顶部状态栏按性质拆为左侧导航组和右侧运行/资源组，不能互相遮挡。现实分钟、游客轮次/倒计时、活力、🍎、收藏墙与 DEBUG 都可点击进入对应页面或操作；现实分钟等同于返回游戏维度，活力等同于点击饼狗。饼狗状态只使用低活力、中等活力、高活力或活力满满，不再显示“状态正常”。

## V9 活动与陪伴日

- 旅行、刷播、冲热、弹琴、睡觉都是读条任务，当前新活动默认 10 秒。
- 开始前均在信息栏二次确认；每次成功领取结果后，陪伴天数增加一天。现实维度的一轮苹果钟完成专注与休息整轮也增加一天。
- running 与 ready 都可取消。取消不增加天数、不发放奖励，也不返还开始时已经消耗的补给或幸运苹果。
- 进行中活动保存 `startedAt`、`endsAt`、`rewardSeed` 和完整 `rewardPlan`。之后改变默认时长不得重算旧活动。
- 睡觉完成后得 1🍎、刷新意愿并播放日夜转场；饼狗必须在床上。
- 拒绝的活动入口变暗并使用 `aria-disabled`，但保留点击反馈；点击不扣资源、不推进随机序列、不打开普通启动确认。

冰箱新增：

- ⚡瓶装速度魔法，2🍎：在读条进行中确认使用，消耗一瓶并让当前任务立刻完成。
- ✨瓶装活力魔法，7🍎：确认使用后，未来七个相伴日内三组意愿都为真。
- 🍎苹果旅行便当让当次旅行遇友概率在未增强基础值上增加 100%；🍀幸运苹果让当前活动对应的收藏概率在未增强基础值上增加 100%。两者分别作用于自己的目标概率，同类加成只取最高值，不在增强结果上继续复合，并统一封顶为 1。

活力按陪伴天数而非自然日计算。领取饼屋活动或完成苹果钟整轮都会推进一天；苹果钟推进到第七日时清除效果并恢复当日偏好。效果有效或本来无需使用时不能重复消耗。

## Bingo、🍎 与 DEBUG

- 房间保持三条 Bingo 小任务；每条完成立即得 🍎，新签发的单条任务最多奖励 3🍎，已经签发的旧任务继续按奖励快照兑现。三项全部完成后以 `√` 保留，等下一次游戏日（陪伴日）推进时刷新；任一任务尚未完成，则跨游戏日继承原任务与完成状态。成功领取任一种饼屋活动或完成苹果钟整轮都会推进一个游戏日。
- 任务只使用能够由网页直接验证的事件。播放器任务在玩家请求打开对应视频时完成。
- 新任务签发前按当前目录和已拥有收藏过滤前置条件；没有对应收藏时不签发分类重看任务，少于两份有效收藏时不签发“重温两份回忆”。
- 导入/缓存准备和 DEBUG 移除收藏也执行同一可达性协调：确定性替换结构合法但已不可达的未完成槽位，保留已完成任务和仍可达任务的对象、进度及奖励快照；畸形任务板不修补，交给最终严格校验拒绝。
- 所有可见金额统一为 `N🍎`；“苹果”文字只用于角色口味、道具名称和“今天也要好好吃苹果”等自然语句。
- DEBUG 可调未来任务时长、五类概率，以及本次页面会话中的刷播轮次时长。刷播时长接受 1–3600 秒，当前轮保持原值，从下一轮开始生效；DEBUG 不默认强制全部意愿。
- 不维护预制全收集存档。DEBUG 提供“一键全收集”和“清空收集”，两者都同时处理收藏与好友。

### 好朋友

旅行以 10% 基础概率先判断朋友，再判断明信片；苹果旅行便当按该未增强基础值增加 100%，默认变为 20%，且不与同类加成复合。两者不能同时出现。朋友旅行相遇时赠固定道具；课代饼、三好兔、心好兔、信号狗、饼哩饼哩依次赠送 2/3/4/3/2🍎，已经认识的朋友仍可再次遇见并照常赠礼。弹琴结束只能从已经认识的朋友中召回来访者，每位已认识朋友增加 15% 来访概率；五位朋友依次赠送 4/6/8/6/4🍎。默认规则下每新增一位朋友都会增加来访率和期望赠礼，且不能通过音乐解锁新朋友。

收藏墙只显示已获得内容；首次获得或相遇后才出现对应分类。空墙文案为“惊喜会在相遇时悄悄出现。”，不显示灰色占位或排序说明。总标题与已出现分类显示 `已拥有/?`，只有按当前动态目录全部集齐后才显示 `已拥有/总数`，例如“好朋友们【4/?】”与“好朋友们【5/5】”；总数不写入存档。朋友卡使用真实角色图铺满裁切，不显示累计收到的 🍎。

## 四排电子琴

- 覆盖 C3–B6 四个完整八度，共 48 个半音，从上到下为 C6、C5、C4、C3。
- 鼠标、触摸可弹全部琴键；物理键盘只映射白键。
- 白键映射从高到低为 `1 2 3 4 5 6 7`、`Q W E R T Y U`、`A S D F G H J`、`Z X C V B N M`。
- 提示语为：“试着从 C6 B5 G5 E5 G5 C6 B5 G5 E5 G5 E5，C6 B5 G5 E5 G5 C6 D6 C6 D6 E6 E6 开始~”。
- 使用 Web Audio 模拟钢琴音色；弹琴读条期间仍可自由交互，琴面板不能产生横向滚动条。

## B 站播放器

- 收藏和唱片机使用构建期静态视频目录；运行时不请求收藏夹 API。
- 选择曲目或打开视频详情即从头请求自动播放；不提供“打开/关闭播放器”的详情按钮。
- 唱片机与详情共用唯一持久播放器。切换信息内容、收藏墙或维度不会意外中断；展开后可直接操作 B 站画面，收起后 iframe 禁用交互，也可用游戏控件显示/隐藏画面、暂停/继续或取消播放。父页计时无法感知用户在跨域 iframe 内手动暂停或拖动，只有游戏控件会同步估算计时。
- 唱片机固定提供八首全站第一，从 Dynamite 到 POWER 按时间顺序排列，不提供自定义曲库。
- 播放状态只保存当前曲目和列表/单曲/随机模式；重新打开页面不恢复正在播放的进度。
- 三种模式均提供上一首、下一首；单曲模式的主动切歌仍切换相邻曲目，只有自动续播时才重播当前曲目。

收藏/视频详情整体比例为 PC 与手机横屏 16:9、手机竖屏 9:16。卡片缩略图和好友头像可使用 `cover`；收藏详情、全屏预览和明信片选择器使用 `contain` 保留完整画面并允许留白，苹果钟运行背景使用 `cover` 铺满并允许裁切；收藏图可下载。

## 现实生活维度

- 只有具备鼠标或触控板精细指针能力的 PC 浏览器可以进入；不使用浏览器品牌、操作系统名单或窗口宽度判断。
- 进入现实维度时创建页面计时租约；每 60 秒心跳把当前有效时长累计进缓存。点 HUD“离开”、离开旅程或 `pagehide` 立即暂停租约，继续缓存只从累计值和新的租约起点接着计时，不补离线时段；异常退出最多累计到最后一次心跳。
- 每实际计时完整 10 分钟，返回时结算基数增加 1🍎。HUD 只显示分钟，点击等同于返回游戏维度。不足 1🍎时直接返回且不创建确认；达到 1🍎后必须回答“是的🥰”或“没有🥺”，前者获得全额，后者获得向下取整的一半。
- 二楼现实入口拆为“刷播”和“冲热（开发中）”。冲热页提供居中的“前往字母建设站”链接：`https://www.weibo.com/u/7878664767`。
- 现实刷播只接受一个可留空的自测 BVID 或完整 B 站视频链接，规范为 BVID 后保存到 V9 存档；其余视频来自 `fid=3963921644` 的构建期同源静态目录。运行时不访问 B 站收藏夹 API、不使用跨域代理。
- 登录刷播通过弹出窗口或新标签页打开带 `autoplay=1&t=0` 的标准 B 站视频页；实验性维度穿透游客刷播使用不可交互的官方播放器 iframe。两者互斥且跨维度运行，开启维度穿透后只在没有登录刷播时自动启动游客刷播。
- 每轮重新随机排列去重后的静态目录，自测 BVID 始终追加在本轮末尾。两种方式共享默认 8 秒且可调为 1–60 秒的视频间隔，以及默认 310 秒的轮次间隔。本轮最后一个登录页面打开或游客 iframe 创建后开始计算轮次间隔；游客刷播保留本轮全部 iframe，到轮次结束时统一销毁并进入下一轮，HUD 跨维度显示当前轮次与下一轮倒计时。
- 可按小时设置本次任务的定时停止，0 或留空为不限时，最长 24 小时；设置在启动时快照。登录时提示尽量不要连续刷播超过 5 小时。
- 打开、轮次和限时共用一个一次性计时器；后台冻结导致回调延迟时，恢复后只推进当前步骤，不连续追赶多轮。弹窗被拦截时等待用户授权并重试；关闭游戏页或主动停止会清理窗口和计时器。
- V9 保留累计完成轮次与最近 10 次任务；每次登录刷播只在主动停止或定时完成时写入一条含起止时间、总轮数和结果的会话记录，0 轮也记录。历史 V6→V7 迁移仍把每条旧轮次独立转换成一条 legacy 会话，不猜测合并。
- “游客刷播”只是模式名称，不保证匿名。官方 iframe 运行在 B 站来源下，浏览器按自身第三方 Cookie 策略决定是否使用已有 B 站会话；父页受同源策略限制，不能读取 Cookie、iframe DOM、播放器状态或响应，也没有绕过 CORS。登录窗口和游客 iframe 都只代表本地发出了跨站加载请求；不把页面打开、iframe `load`、HUD 轮次或本地计时解释为真实播放、播完或计数增加。
- 一楼“工作”先显示持久化待办 CRUD，再显示明信片选择器；苹果钟提供 25+5、50+10、90+15 三组专注与休息周期。
- 启动后把选定明信片以 `cover` 作为全屏背景，并展示陪伴饼狗、待办和可操作的游戏播放器控件。专注到点进入休息，完成整轮才 `companionDays + 1`；重复 tick、未到点、截止前取消、普通现实停留结算、待办操作或单独的待办到期均不增加天数。

## V9 存档

- 浏览器缓存是日常主存档。标题页在存在缓存时显示“继续”，并始终提供“全新旅程”和“本地存档”；`.bingo` 用于备份和跨浏览器导入。
- 通过“全新旅程”或“本地存档”覆盖缓存、检测到更新时下载旧档；首次获得新的全站第一或认识新朋友构成关键节点，每到关键节点、每隔三天也会自动请求备份。
- 新导出业务 payload 为 `schemaVersion: 9`，封套 `gameVersion: 0.9.0-demo.1`。
- 导入支持严格 V1–V9。顺序是：原始摘要校验 → 历史 schema 解析 → 迁移至 V9 → 规则规范化 → 当前目录协调 → 最终语义校验。
- 浏览器缓存成功迁移、规范化、目录协调或暂停旧页面租约后，同步写回 V9 payload、`gameVersion: 0.9.0-demo.1` 与新的 `updatedAt`；外层 `cacheVersion` 仍为 1。
- V1–V5 的进行中活动保留原始绝对时间和奖励计划；旧任务不会因当前默认 10 秒而被改写。
- 历史 V6→V7 刷播记录迁移规则保留；V7→V8 新增 `selfTestBvid: null` 与 `dimensionPenetrationEnabled: false`。
- V8→V9 为现实停留新增 `activeDurationMs` 与可暂停的 `leaseStartedAt`。旧 V8 活跃停留没有心跳证据，迁移时累计时长归零；不使用缓存更新时间推断在线时长或补发离线奖励。
- V9 保存用户名、陪伴天数、🍎、七种道具、收藏、好友、任务、意愿、当前活动、魔法、现实计时租约/结算、待办、完整苹果钟、播放器当前 BV/索引/循环模式、刷播累计轮次与最近 10 次任务记录，以及单个可选自测 BVID 和维度穿透开关。
- 不保存收藏总数、分类解锁、全站第一指针、好友总数或视频元数据。目录追加后旧档自然把新 ID 视为未拥有。
- 离开房间直接返回标题页并保留缓存；仅缓存写入失败时注册浏览器离开提醒。

## PWA 与浏览器能力边界

- “检查更新”只保留在标题页，结果使用临时提示；检测到或安装新版本时先备份缓存进度。
- 网页在旅程入口的明确用户手势后启动守候音频并保持开启，不在状态栏显示技术开关。它是尽力保活，不能绕过浏览器或操作系统后台冻结。
- 移动主输入设备在旅程运行且页面可见时请求 Screen Wake Lock；隐藏时释放、重新可见时再请求。不支持或拒绝权限时静默降级，且不承诺后台持续执行。
- 通知必须由用户主动授权；页面完全关闭、系统休眠或后台被冻结时不保证准点弹出，重新聚焦后按绝对时间补检查。
- 第三方有声自动播放可能被浏览器拦截；UI 不显示实现细节或不可靠的成功状态。
- 网页、Apple Touch 与 PWA 图标统一使用饼狗头像 PNG。
